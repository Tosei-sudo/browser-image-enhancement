# 画像ビューア

`browser-image-enhancement/openlayers` を使った画像閲覧サイトです。画像はサーバーに送らず、ブラウザの中で読み込み・補正します。

## できること

- **ローカルファイルを開く**: ヘッダーのフォルダボタン、または表示エリアへのドラッグ＆ドロップ。GeoTIFF と普通の画像（PNG・JPEG・WebP など）のどちらも開けます。複数のファイルをまとめて選べます。ローカルファイルはタイル（ストリップ）単位で必要な部分だけ読むので、数 GB の COG でもすぐ開けます。オーバービューのない GeoTIFF は、開くときにワーカーで全体を一度読んで縮小版（オーバービュー）を作り、元ファイルの後ろにつないで開くので、縮小表示でも粗くならず、メモリも縮小版の分（最大 128 MB 程度）しか使いません（URL で開く COG はそのまま）。大きな画像（約 1,600 万画素超）は縮小版の完成を待たずにすぐレイヤーに追加し、生成中は 1/2 以上に拡大したときだけ生画素で表示します（引いた状態では描かず、地図左下に「RSET 生成中: 1/2 以上に拡大すると表示します」と出します）。生成が終わると補正やバンド割当はそのままに、どの縮尺でも表示されるようになります
  - **外部 OVR（GDAL の .ovr）**: GeoTIFF と一緒にその `.ovr`（`gdaladdo -ro` や QGIS の外部ピラミッドで作られる `image.tif.ovr` または `image.ovr`）を選ぶかドロップすると、RSET を生成せずに .ovr の各レベルをそのまま使います。どちらのファイルも画素はコピーせず、ディレクトリだけ読んでつなぐので、大きな .ovr でもすぐ開けます。JPEG（YCbCr）圧縮の .ovr や BigTIFF にも対応します。バンド数・ビット深度・縦横比が画像と合わない .ovr はその旨を表示して RSET を生成し、ファイルに RSET が内蔵されている画像では（GDAL と同じく）内蔵のほうを使います。ブラウザは選んだファイルの隣のファイルを読めないので、.ovr は画像と一緒に選んでください（一緒に選んだファイルは「最近」からもまとめて開き直せます）
  - **NITF・SICD**: NITF 2.1 / 2.0（NSIF 1.0）の画像（`.ntf`・`.nitf`・`.nsf`・`.r0`）と SICD（`.sicd`・`.ntf`）を GeoTIFF と同じように開けます。画素はコピーせず、ファイルの前に TIFF の目次を付けて NITF のブロックをそのまま読むので、大きなファイルもすぐ開き、RSET も GeoTIFF と同じように作ります。非圧縮（IC が NC、ブロックマスク付きの NM）は 8〜64 bit の整数・実数、バンドの並び（IMODE B・P・S・R）を問いません。JPEG（C3・M3、8 bit）と JPEG 2000（C8・M8、8・16 bit）で圧縮された NITF も開けます。どちらもブロック（タイル）ごとに必要な分だけ読み、JPEG 2000 は同梱の OpenJPEG（WebAssembly）で解くので、閉じたネットワークやオフラインでも使えます。それ以外の圧縮（可逆 JPEG・ベクトル量子化など）の NITF は開けず、その旨を出します。位置は RPC00B / RPC00A（ICHIPB の切り出しも考慮）があれば RPC で、なければ IGEOLO の四隅（度・度分秒・UTM・MGRS）で置きます。SICD（RE32F_IM32F・RE16I_IM16I・AMP8I_PHS8I）は複素数から振幅を求めて 1 バンドの画像として表示し（AMP8I_PHS8I は振幅テーブルを使用）、XML の四隅（ImageCorners）で地図に置きます（SAR の幾何を厳密に解くのではなく四隅の間を補間します）。画像セグメントに分かれた大きな SICD はつないで表示します。情報欄とメタデータに NITF のヘッダーや SICD の観測情報（センサー・モード・偏波など）を出します
  - **RSET（縮小版）の表示**: レイヤー一覧の各画像に「RSET」（ファイルに内蔵）、「RSET (OVR)」（外部の .ovr ファイル）、「RSET生成」（このビューアーで作成）、「RSET生成中」、「RSETなし」のタグを出し、情報欄に各レベルの縮小率（1/2〜1/256 など）を表示します。地図の左下には、選択中の画像を今どこから表示しているか（「表示: RSET 1/8」または「表示: 生画素」）を出し、ズームに合わせて切り替わります。RSET の生成中は地図の上部にファイルごとの進捗バーを表示します
  - **最近開いたファイル**: File System Access API のあるブラウザ（Chrome・Edge）では、フォルダボタンやドラッグ＆ドロップで開いたファイルを覚えておき、ヘッダーの「最近」から再読み込み後も選び直さずに開き直せます（読み取りの許可だけ聞かれます）。一緒に選んだファイル（画像と .RPB、Shapefile の各ファイル）は一緒に開き直します。履歴はブラウザ内（IndexedDB）にだけ保存し、ファイルの中身はコピーしません
- **Shapefile・GeoJSON・GeoPackage**: Shapefile は .zip のまま、または .shp・.dbf・.prj（あれば .cpg）を一緒に選びます。属性は属性テーブルに表示され、地図やテーブルで選択できます。属性の文字コードは .cpg に従い、.cpg がなければ UTF-8 か Shift_JIS かを自動で判定します。.prj がない Shapefile は経緯度のときだけ開けます
  - **GeoPackage**: .gpkg の地物テーブルごとに 1 レイヤーとして開きます（タイルや属性だけのテーブルは開きません）。座標系はファイルの `gpkg_spatial_ref_sys` に従い、ビューアが知らない EPSG コードでもファイルに入っている WKT で投影します。SQLite は公式の WebAssembly 版を、最初に GeoPackage を開いたときだけ読み込みます（約 0.9 MB）
  - **大容量の Shapefile**: .shp が 48 MB を超えるか地物が 5 万件を超える Shapefile（.zip の中でも）は、全体をメモリに読まずに、ワーカーで少しずつブラウザ内（IndexedDB）へ書き出し、空間インデックス（R-tree）と縮尺ごとに頂点を間引いたコピーを作ります。地図には表示範囲（と少しの余白）の地物だけを読み込み、縮小時は頂点と 1 ピクセルより小さな地物を間引いて描きます。地図を動かすと新しい範囲を読み込み、属性テーブルにはそのとき読み込んでいる地物が出ます（選択中の地物は動かしても選択されたまま）。読み取り専用で、書き出しは読み込んでいる地物だけです。ブラウザ内のコピーはレイヤーを閉じると消えます（再読み込みなどで残ったものは次に開いたときに消します）。3,000 万頂点（.shp 480 MB）の Shapefile で、従来はブラウザ全体で 5 GB 以上使っていたところ約 1.5 GB で開けます
  - **ファイルの編集**: 一覧の ✎（編集）で Esri と同じ編集ツールバーが出て、地物の追加・形状編集・削除・属性の変更ができます。追加する図形はファイルの種類に合わせます（Shapefile と GeoPackage はファイルの型、GeoJSON はツールバーで点・線・面を選びます）。「保存」でファイルを同じ形式・同じ座標系で書き直します。フォルダボタンや「最近」から開いたファイルは、ブラウザの許可を得て元のファイルに上書きし、それ以外（ドラッグ＆ドロップ、許可しなかった場合など）は同じ名前でダウンロードします。GeoPackage は編集した行だけを書き換えるので、ほかのテーブル・列・空間インデックスはそのまま残ります。.zip の Shapefile は .zip ごと書き直し、別々に選んだ Shapefile は .shp・.shx・.dbf・.cpg をすべてフォルダボタンで選んでいれば上書き、そうでなければ .zip でダウンロードします。Shapefile の属性は UTF-8（.cpg 付き）で書きます。5 万件を超えて先頭だけ読んだ GeoJSON・Shapefile は、書き直すと残りが消えるので編集できません
- **CSV**: .csv・.tsv を開くと、地図には何も描かず、属性テーブルに表として表示します（読み取り専用）。区切り（カンマ・タブ・セミコロン）と文字コード（UTF-8・Shift_JIS）は自動で判定し、列の型は値から数値（整数・小数）か文字かを決めます。「プロセッシング」の「XY 座標からポイントを作成」でポイントの一時レイヤーにできます
- **画像カタログ**: `config.json` の `imageCatalogs` に Esri フィーチャーサービスの画像カタログ（画像ごとにフットプリントのポリゴンと属性を持つレイヤー）を書くと、ヘッダーに「画像カタログ」が出ます。撮像日・センサー・角度・表示範囲で検索し、結果を新しい順に一覧と地図上のフットプリントで表示します。一覧の見出しで並べ替え、行や地図上のフットプリントのクリック（Ctrl・Shift で複数）で選び、「開く」かダブルクリックで COG を開きます。開いた画像の情報欄にはカタログの属性（画像ID・撮像日時など）を出します。「詳細条件」では登録日・システム登録日・方位角の範囲（350〜10 のように北をまたぐ指定も可）と SQL の条件も指定できます。画像の場所がローカルパスの行（「ローカル」と表示）は、`pathMappings` に書いた対応で開きます（下記。「パスをコピー」でパスも控えられます）
  - **似た画像を探す**: 比較用に、同じセンサー・近い角度（オフナディア角など）・近い方位角で同じ範囲を撮った画像を探します。カタログから開いた画像のレイヤーを右クリックして「似た画像を探す…」、またはカタログの一覧で 1 枚選んで「似た画像を探す」。許容幅（既定は角度 ±5°・方位角 ±20°、北をまたいでも可）、同じセンサーに限るか、比べる画像の範囲を何 % 以上写しているかを画面上で変えて検索し直せます（許容幅はこのブラウザに残ります）。結果は似ている順（範囲の重なり・角度と方位角の差）で、重なりの割合を列に出し、比べる画像のフットプリントは赤い破線で地図に残ります。撮像日や SQL の条件も組み合わせられ、「ふつうの検索に戻る」で通常の検索に戻ります
- **撮像計画**: 「ツール」→「撮像計画」で、衛星カタログ（`config.json` の `satelliteCatalogs`。Esri フィーチャーサービスのレイヤーかテーブルに、衛星ごとの TLE と諸元を持つもの）の衛星が、レイヤーの地物（または選択中の地物、地図でクリックした地点）を次にいつ撮像できるかを計算します。軌道は SGP4（satellite.js）で伝搬し、パスごとに対象へ最も近づく時刻（オフナディア角が最小の時刻）を求め、その角度が衛星の範囲内（最大・最小オフナディア角）で、見られる向き（右・左）に入り、光学衛星なら太陽高度が足りるときを撮像機会とします。結果は時刻順の一覧（日時・衛星・対象・オフナディア角・右/左と北行/南行・太陽高度・被覆）で、行を選ぶと地図に地上軌跡・届く範囲の端（最大オフナディア角）・撮像範囲（観測幅のシーン）と衛星の位置を描きます。撮像範囲は観測幅 × シーン長の枠で、1 パスでは観測幅 1 列ぶんを、連続撮像シーン数（`scenesPerPass`、既定 1）までパスに沿って続けて撮ります（例: 3 なら観測幅 × シーン長 3 枚ぶんの帯）。一覧の被覆には撮る枚数と、対象全体を覆うのに要る「横 n × パス方向 m」を出します。ポリゴンは内側に格子点（約 600 点）を置いて、その回のシーンが対象の何 % を撮れるか（被覆）を出します。1 回で覆えない広いポリゴンでは、表示が「組み合わせ（全域を最短で）」になり、すべての衛星のパスを時刻順に見て、まだ撮れていない部分を最も多く撮れる位置にシーンを置きながら、目標（既定 95%）に届くまでつなぎます。一覧には各回の追加分と累計を、地図には選んだ回と同じ対象の他の回を番号つきで描きます。組み合わせでは、同じパスの 1 シーン（観測幅 × シーン長）に収まる近い地点をまとめて 1 回の撮像にし（「近い地点を 1 シーンにまとめる」。一覧に「#シーン番号（地点数）」、ステータスに総シーン数）、地図にはそのシーンを地点がすべて入る位置に描きます。衛星ごとの撮像間隔（1 回撮ってから次まで何分）と 1 日の上限回数を登録しておくと、組み合わせでは対象をまたいでそれを守り、守るために見送ったパスの数を表示します。「詳細条件」の「優先度の属性」で対象レイヤーの数値の属性（名前に priority・優先 を含むものを初期選択）を選ぶと、組み合わせでは優先度の高い地物から衛星の撮像を割り当て、低い地物は残った撮像機会に入れます（撮像間隔・1 日の上限で取り合うとき、高い方が先に撮れます。既定は値が小さいほど優先、「大きいほど優先」にも切り替え可。値のない地物は最後）。一覧と CSV に優先度の列が付きます。「名前の属性」では一覧・CSV・レイヤーで対象の名前に使う属性を選べます（自動は name・名称 などを探し、なければ ID。計算後に変えても計算し直さずに一覧が変わります）。一覧の見出しで並べ替え、「衛星・対象ごとに最初の機会のみ」で絞れます。「CSV 保存」で一覧を、「レイヤーとして追加」で撮像範囲を撮像日時つきの一時レイヤーにします（タイムラインで絞れます）。「詳細条件」の衛星は タイプ（光学・SAR）→ シリーズ → 固有名 の 3 階層に折りたたまれ、グループのチェックで中の衛星をまとめて選べます。発注リードタイム（`leadTime`）がある衛星は、計算した時点からその時間より近い機会を除き、一覧の日時に発注期限を添えます（CSV にも出ます）。「詳細条件」では衛星の選択、日照条件と太陽高度、地物ごとかまとめてか、TLE の貼り付け（カタログがなくても使えます。撮像間隔・1 日の上限も指定できます）を指定できます。計算は Web Worker で行い、元期から 14 日を超えた TLE には「TLE 古い」と出します。3D 表示中は、選んだ回の軌道をその高さに描き（地上軌跡まで半透明の幕を下ろして立体的に）、衛星を本体・太陽電池パネル・センサーのモデルで描いてセンサーを撮像範囲の中心へ向け、センサーから撮像範囲へのビーム（半透明の面と四隅への線、視線の点線）と、衛星名・日時・オフナディア角のラベルを付けます。組み合わせの他の回は淡く描きます。「範囲へ移動」は、軌道を斜め横から見下ろす位置へカメラを動かします
- **STAC 検索**: 「ツール」→「STAC 検索…」で、STAC API（STAC API 1.0 の `/search`。既定は Earth Search の Sentinel-2 L2A・Landsat C2 L2）からシーンを探します。範囲（表示範囲・地図に描いた四角・指定なし）、撮像日、雲量（`eo:cloud_cover`）の上限、コレクションで検索し、サムネイル・撮像日時・雲量・コレクションの一覧と地図上のフットプリントで新しい順に表示します（行を指すとフットプリントが強調され、フットプリントのクリックでも選べます）。続きは「さらに読み込む」で API の `next` リンクから読みます。「開く」かダブルクリックで COG のアセットを開きます: `visual`（トゥルーカラー）があればそれ、なければ赤・緑・青のアセットを開いて RGB 合成のダイアログに割り当てた状態で出します（「実行」で 1 枚に）。1 件だけ選んだときは「開くもの」でフォールスカラー（NIR・赤・緑）や個別のアセット、「バンドを選んで合成…」で好きな 3 つも選べます。バンド名は `eo:bands`（`bands`）の common name と名前、アセットのタイトルから表示します。「詳細」では 1 ページの件数と、静的カタログ・コレクション・アイテム（JSON）の URL からの読み込み（`child`・`item` のリンクをたどります。最大 500 件・100 ファイル・4 階層）も使えます。開いた画像の情報欄にはアイテムの ID・コレクション・撮像日時・雲量・アセットを出します。`config.json` の `stacCatalogs` でカタログを替えたり並べたりでき、`"stacCatalogs": []` にするとメニューから消え、外へは何も送りません（下記）
- **COG を URL で開く**: ヘッダーのリンクボタンから URL を入力。`?url=<COG の URL>` を付けたリンクで開くと、起動時にその COG を開きます（複数指定可）。Esri のイメージサービス（`…/ImageServer`）やマップサービス（`…/MapServer`）の URL を入れると、そのサービスの画像レイヤーとして開きます（下記。トークンが必要なサービスは「サービスを追加」から）
- **複数の画像を重ねる**: 左の一覧で表示切替・不透明度・重なり順・移動・閉じるを操作できます。一覧で選んだ画像に右上の補正パネルが効き、補正は画像ごとに保持されます
- **レイヤーのグループ**: 一緒にドロップ（または一緒に選択）したファイルから 2 つ以上のレイヤーができると、名前の共通部分（`LC08_L1TP_107035_B4.TIF` などなら `LC08_L1TP_107035`。共通部分がなければ開いた時刻）を名前にしたグループにまとまります。グループの行のチェックで中のレイヤーをまとめて表示・非表示（それぞれのチェックは保たれます）、名前のクリックでたたむ・開く、グループの「不透明度」で中のレイヤー全部の不透明度、⤢ でグループ全体へ移動、↑↓ でグループごと重なり順を変え、× で中のレイヤーごと閉じます。⋯（または右クリック）で名前の変更・まとめて表示／非表示・グループの解除ができ、名前はダブルクリックでも変えられます。レイヤーの行を右クリックすると「新しいグループに入れる」「グループ「…」に入れる」「グループから出す」が出ます。グループの中の ↑↓ はグループの中で動かし、グループに入っていないレイヤーの ↑↓ はグループを丸ごと飛び越えます。グループはプロジェクトファイルにも保存されます
- **大量の画像を開く**: 画像を一度に何枚もドロップすると、4 枚ずつ並行して読み込み、選んだ順に準備のできたものから一覧（グループ）に加えます。グループの行には「読み込み中 12/40」と進み具合を出し、地図は 1 枚ごとに飛ばず、最初の画像と最後に全体へ合わせます。13 枚以上ならグループはたたんだ状態で始まります。8 枚以上のときは小さな画像も大きな画像と同じく RSET の完成を待たずに地図へ出し、RSET は 2 枚ずつ順番に作ります（表示範囲に入っている画像から先に。閉じた画像の分は作りません）。進捗パネルには作成中のものと「ほか N 件の RSET が順番待ち」を出します。補正・着色・重ね方を変えていない画像は WebGL のキャンバスを共有するので、何十枚開いても描画が途切れません（ブラウザの WebGL コンテキスト数の上限に当たりません）
- **補正**: 明るさ・コントラスト・露出・ガンマ・彩度・色温度・レベル・シャープ、表示範囲に合わせた DRA（「範囲を固定」で画像ごとに今のレンジを保ったまま移動・拡大できます）、バンド割当。WebGL2 が使える環境では GPU で補正するので、スライダーにそのまま追従します。16bit や float の画像（Landsat など）は元の値からバンドごとに引き伸ばして表示します。DRA がオフのときは QGIS の既定と同じく画像全体の 2〜98 %、オンのときは DRA の設定で表示範囲から引き伸ばします。「RGB 連動」をオンにすると 3 バンドに同じ範囲を使うので、大気の散乱で値が高い青バンドが持ち上がり、青っぽく見えます
- **画像ビューアの表示**: 既定では背景地図はなく、市松模様の背景に画像だけを表示します。開いた画像に合わせて表示範囲を調整します。GeoTIFF 同士は位置情報で重なるので、同じ範囲の画像を重ねて比べられます
- **背景地図**: ヘッダーの「背景地図」で、なし・地理院 標準・地理院 淡色・地理院 写真・地理院 ベクトル・OpenStreetMap・OpenStreetMap（Esri ベクトル）を切り替えられます（補正はかかりません）。一覧は `config.json` で変えられ、ラスタータイルのほかベクタータイル（ArcGIS の VectorTileServer〔ArcGIS Online・Enterprise・Data Appliance〕、Mapbox / MapLibre のスタイル JSON、`{z}/{x}/{y}.pbf` のタイル）も使えます
- **サービスのレイヤー**: ヘッダーの「サービスを追加」で URL を入れると、種類（WMS・WMTS・WFS・WCS・OGC API（Features・Tiles・Coverages）・Esri のフィーチャー・マップ・イメージサービス）を自動で判定してレイヤーの一覧を出します。選んだレイヤーは画像と同じ一覧に入り、表示切替・不透明度・重なり順を操作できます
  - **WMS・WMTS**: 画像と同じように補正パネルで補正できます（GPU で補正するので、サーバーが CORS を許可している必要があります。許可していないサーバーは補正なしで表示します）。WMS は地図をクリックすると、その地点の属性（GetFeatureInfo）を属性テーブルに出します。WMTS はタイル行列セットと画像形式を選べます
  - **WFS・Esri フィーチャーサービス**: 地物をすべて読み込み（1 レイヤー 5 万件まで）、Esri はサービスの描画設定（単一シンボル・個別値・等級区分）で表示します。Esri のマルチパッチ（3D）レイヤーは、2D では外形（`multipatchOption=xyFootprint`）を、3D 表示では外形を最低〜最高の高さ（`extent`、ArcGIS Enterprise 10.9 以降）で立ち上げた立体を描きます（細かい形は REST の JSON で取れないため。細かい 3D はシーンサービスで開いてください）。WFS は 2.0.0・1.1.0・1.0.0 に対応し、GeoJSON を出せるサーバーでは GeoJSON、それ以外は GML で読みます
  - **Esri イメージサービス（ImageServer）**: `exportImage` で 512 px ずつ描き、WMS と同じく補正パネルで補正できます。一覧の ⚙（表示ルール）で、どの画像をどう重ねて描くか（モザイクルール）とラスター関数を変えられます。ふだん使うのは「条件」（カタログの属性の SQL。属性・比べ方・値を選んで「条件に追加」でも作れ、値はサービスにある値から選べます。条件に合う画像の数をその場で数えます）、「並び順」（上に重ねる画像を属性の大きい順・小さい順で。撮像日の新しい順など）、「ラスター関数」（サービスが持つもの、または「なし（保存されている値）」）です。「詳細」では重ね方（北西・中心・直下視・シームライン・画像 ID 指定など）、並び順の基準値、重なった画素の値（上・下・最小・最大・平均・ブレンド・合計）、バンド（R・G・B）、レンダリングルールの JSON を指定できます。「表示範囲を画像として開く」で、いまの表示範囲を保存されている値の GeoTIFF（`exportImage` の TIFF。サービスの上限の大きさまで）として取り込み、ローカルの画像と同じようにバンド割当・ストレッチ・補正をかけられます。地図をクリックすると、その地点の画素値と下にある画像（表示中・下に隠れている）の属性を属性テーブルに出し、フットプリントを強調します。サービスにタイルキャッシュ（Web メルカトル）があれば、表示ルールが既定のときはキャッシュを使います。`config.json` の `serviceRules` に名前付きのルールを書いておくと、ダイアログの「ルール」から選べ、`default` のルールは開いたときに使います（下記）
  - **Esri マップサービス（MapServer）**: レイヤーの一覧の先頭に「（地図画像）」が出て、サーバーが描いた地図を 1 枚のレイヤーとして重ねます（フィーチャーレイヤーはこれまでどおり個別にベクターとして追加できます）。⚙（表示ルール）で描くレイヤーと、レイヤーごとの属性の条件（`layerDefs`）を変えられます。既定の表示のままでタイルキャッシュ（Web メルカトル）があればキャッシュを、それ以外は `export` で描きます。地図をクリックすると、描いているレイヤーの地物を `identify` で属性テーブルに出します
  - 表示ルールは共有リンク（`?service=`）とプロジェクトファイルにも入り、情報欄に今のルールを出します
  - **トークン**: 認証が必要な Esri サービスは、ダイアログの「トークン」に入力します。トークンは保存せず、共有リンクにも含めません
  - **OGC API – Features**: ランディングページかコレクションの URL を入れると、地物のコレクションを一覧にします。GeoJSON をページごとに（`next` のリンクをたどって）読み、WFS と同じく 1 レイヤー 5 万件まで、属性テーブル・選択・スタイル・書き出しが使えます。「範囲」で全体・表示範囲・選択中の地物の範囲を選べ、「詳細」で条件を指定できます（サーバーが Part 3 と CQL2 に対応していれば CQL2 テキストの `filter`、そうでなければ `属性=値` を `&` か `AND` でつないだもの）。Web メルカトルを出せるサーバー（Part 2）ではその座標系で、それ以外は CRS84 で読みます。属性の型は queryables から取ります。Part 4（create-replace-delete）に対応したサーバーでは ✎ で編集でき、追加は POST、変更は PUT、削除は DELETE で 1 件ずつ送ります
  - **OGC API – Tiles**: データセット全体と各コレクションのタイル（WebMercatorQuad のみ）を追加できます。「形式」でベクタータイル（MVT。レイヤーの色で描きます）か地図タイル（PNG・JPEG。WMTS と同じく補正パネルで補正できます）を選びます
  - **WCS・OGC API – Coverages（画素値）**: WCS 2.0 の GetCoverage（GeoTIFF）、OGC API – Coverages の `coverage?bbox=…&f=geotiff` で、表示範囲・選択中の地物の範囲・全体の画素値をそのまま読み、ローカルの GeoTIFF と同じ画像として開きます（バンド演算・ストレッチ・ゾーン統計などが実際の値で使えます）。大きさは 1 辺 8,192 画素・合計 4,000 万画素まで（WCS は縮小の拡張 `SCALEFACTOR` に対応したサーバーなら縮小して読み、対応していなければ範囲を狭めるよう知らせます）、ファイルは 1 GB までです。プロジェクトには取得した URL を保存し、開き直すと読み直します
  - **WFS-T**: GetCapabilities に Transaction があり、DescribeFeatureType で名前空間とジオメトリがわかる WFS レイヤーは、Esri と同じ ✎ で編集できます。「保存」で追加・更新・削除をまとめて 1 つの Transaction（2.0.0 は GML 3.2、1.1.0 は GML 3.1.1、1.0.0 は GML 2）で送り、TransactionSummary の件数を状態欄に出します。サーバーが例外を返したときは、すべての変更を未保存のまま残して理由を出します
- **属性テーブル**: 地図の下に、選択中の WFS・Esri レイヤーの属性を表示します。「全件」と「選択中のみ」を切り替えられます。行をクリックすると地図で強調表示され、ダブルクリックでその地物へ移動します。見出しで並べ替え、検索欄で絞り込み、「列」で列の表示切替、「CSV 保存」で表示中の行を保存できます。上端をドラッグすると高さを変えられます
  - **複数選択**: Ctrl（Mac は ⌘）+ クリックで追加・解除、Shift + クリックで直前にクリックした行からの範囲を選びます。行頭のチェックボックスでも追加・解除でき、見出しのチェックボックスは表示中の行（検索で絞り込んだ行）をすべて選びます。テーブルにフォーカスがあるとき Ctrl+A で表示中の行をすべて選択、Esc で選択解除です。地図では地物を Ctrl / Shift + クリックで追加、Ctrl（⌘）+ ドラッグで囲んだ範囲の地物を選択に加えます
  - **右クリックメニュー**: 行を右クリックすると「地物にズーム」「行をコピー」（タブ区切りなので表計算ソフトに貼り付けられます）「選択を解除」が出ます。選択中の行を右クリックすると選択中の全件が対象になります。削除できる Esri レイヤーでは「削除…」も出て、確認のあと編集を始めて削除します（「保存」を押すまでサーバーには送られず、「元に戻す」で戻せます）。Delete キーでも同じように削除できます
- **書き出し**: WFS・Esri・GeoJSON・Shapefile・GeoPackage のどのベクターレイヤーも、一覧の ⇩（書き出し）から GeoJSON（.geojson）・Shapefile（.zip）・GeoPackage（.gpkg）に書き出せます。座標系は WGS 84（既定）・Web メルカトル・元の座標系（ファイルから開いたレイヤー）から選べ、地図や属性テーブルで選んだ地物だけを書き出すこともできます。未保存の編集も含め、地図に見えているとおりに書き出します。Shapefile は属性名を 10 バイトまでに切り詰め（重なれば `_1` などを付けます）、文字は UTF-8（.cpg 付き）、点・線・面が混ざったレイヤーは種類ごとに別の Shapefile にして 1 つの .zip に入れます。GeoPackage には空間インデックス（R-tree）も作ります。日付は GeoJSON では ISO 8601 の文字列、Shapefile では日付型、GeoPackage では DATE / DATETIME 型です
- **表示範囲を保存**: 「ツール」メニューの「表示範囲を保存」で、いま地図に見えている範囲をファイルにします。「見たまま」は表示中のレイヤーを補正・ベクターのスタイルとラベル・背景地図ごと 1 枚にして PNG か GeoTIFF（8bit RGBA、地図の座標系の位置情報付き。地図が回転していれば回転付きの変換で書きます）で保存します。大きさは画面と同じほか 2 倍・4 倍（同じ範囲を細かいタイルで描き直します。長辺 8192 px まで）を選べます。画像のない部分は透明です。CORS を許可していないサーバーのレイヤーは読み取れないので含めず、その件数を状態欄に出します。「選択中の画像の元データ」は選んだ GeoTIFF の表示範囲を、補正をかけない元の値のまま全バンド・同じデータ型・nodata・座標系で GeoTIFF に切り出します（約 6,400 万サンプルを超えるときは RSET から読みます。オルソ補正をずらしたレイヤーはずらした位置で書きます）
- **スタイル・ラベル**: WFS・Esri・GeoJSON・Shapefile・GeoPackage・一時レイヤーのどのベクターレイヤーも、一覧の ◐（スタイル・ラベル）で見た目を変えられます。表示方法は「単一シンボル」（塗りの色と不透明度、線の色・幅・不透明度・線種、点の形と大きさ）と「属性で色分け」（属性の値ごとに色を付け、値ごとに表示・非表示を切り替え。値が 200 種類を超える分は「その他」）、「数値で段階に色分け」（数値の属性を等間隔・等量（分位数）・自然分類（Jenks）で 1〜20 段階に分け、色のグラデーション（赤・青・緑・Viridis など、逆順も可）で塗り分け。段階の境目は数値を打って動かせます）、Esri レイヤーでは「サービスの表示のまま」も選べます。色分けの「色を付ける先」で、分類・段階の色を塗り・枠・その両方のどれに付けるかを選べ、各行の「枠」を押すとその値（段階）だけの枠の色・幅・線種を設定できます（空欄・「共通」はシンボルの設定のまま、「共通に戻す」で元に戻ります。線のレイヤーでは線の幅と線種）。行ごとの枠は SLD・QML・Esri Web マップの書き出しと読み込み、プロジェクトにも保存されます。「縮尺で表示を切り替える」（普段は折りたたみ）で、これより縮小・拡大したらレイヤーを隠す縮尺を 1:N で指定でき（「いまの縮尺」で地図の縮尺を入れられます）、範囲外のレイヤーは一覧で薄く表示されます。ラベルにも「これより縮小したら隠す」縮尺を指定できます。ラベルは属性を選ぶと、文字の大きさ・色・太字・縁取りの色と幅を設定でき、重なるラベルは自動で間引きます（「重なるラベルも全部表示する」で全部表示）。編集中は地図にすぐ反映され、OK で確定、キャンセルで元に戻ります。設定はブラウザ（localStorage）にレイヤーごと（サービスは URL とレイヤー名、ファイルは種類と名前）に保存され、同じレイヤーを開き直すと復元されます。一時レイヤーのスタイルはレイヤーを閉じると消えます。Shapefile・GeoPackage に書き出すときは「スタイルも保存する」（既定でオン）で、スタイルを QGIS と同じ形で一緒に保存します（Shapefile は同じ名前の .qml、GeoPackage は layer_styles テーブル）。QGIS で開くと同じ見た目になり、このビューアで開き直しても元のスタイルに戻ります。QGIS で作ったスタイル（.qml・layer_styles）も、単一シンボル・分類・段階の色、線の幅、点の形と大きさ、ラベル、縮尺を読み取ります
- **プロセッシング**: ヘッダーの「プロセッシング」で、開いているベクターレイヤー（全件か選択中の地物）に QGIS のプロセッシングのような処理をかけます。結果は「一時」の印が付いた一時レイヤーとして一覧に入り、ブラウザ内（IndexedDB）に保存されるので、再読み込みしても残ります（× で閉じると消えます）。一時レイヤーもほかのベクターレイヤーと同じく ✎ で編集（「保存」でブラウザに保存）、⇩ で GeoJSON・Shapefile・GeoPackage に書き出せます
  - **ファイルを直接入力に**: 各ツールの入力（レイヤーや画像の選択）の横の 📂 で、地図に追加していないファイルをそのまま使えます（ArcGIS・QGIS のツールダイアログと同じ）。「ファイルを選ぶ…」、「最近」のファイル、URL（COG・GeoJSON など）から選べ、開いたファイルは地図にも一覧にも入らず、表示範囲も動きません。開いたファイルは 📄 の印で、ページを閉じるまでほかのツールでも選べます。モザイクでは 📂 で選んだ画像がつなぐ画像の一覧に加わります。対象はベクターのプロセッシング、ゾーン統計、バンド演算、変化抽出、土地被覆分類（画像と学習ポリゴン）、自動位置合わせ、RGB 合成、モザイク、パンシャープンです
- **新規レイヤー**: 「ツール」→「新規レイヤー…」で、空の一時レイヤーを自分で設計して作れます（QGIS の「新規一時スクラッチレイヤー」にあたります）。名前、ジオメトリ（ポイント・ライン・ポリゴンとそのマルチ、または「指定しない」で描くたびに選ぶ）、属性（名前・型〔文字列・整数・小数・日付〕・必須）を決めます。属性の「詳細」では表示名・既定値（新しい地物に最初から入る値）・文字数の上限・数値の範囲（最小・最大）・候補値（`1=住宅, 2=店舗` のように書くと属性テーブルで選べます）も指定でき、「ほかのレイヤーの属性をコピー」で開いているベクターレイヤーの属性とジオメトリをひな形にできます（地物はコピーしません）。書き出しの既定の座標系は「詳細設定」で選べます。作ると編集が始まって「追加」が押された状態になるので、地図をクリックすればすぐ描けます。ほかの一時レイヤーと同じくブラウザに保存され、⇩ で書き出せ、プロジェクトにも保存されます
- **格子を敷き詰める**: 「ツール」→「格子を敷き詰める…」（プロセッシングの「処理」からも選べます）で、範囲に正方形・六角形・三角形のセルを任意の大きさで敷き詰めた一時ポリゴンレイヤーを作ります（QGIS の「グリッド作成」にあたります）。範囲は地図に描いた四角・多角形（既定）、レイヤーの地物（選択中だけも可）、今の表示範囲、経緯度で打ち込んだ西・南・東・北から選びます。「測地線」では WGS 84 楕円体上の距離（m・km）で、範囲の中心からの距離が正しい正距方位図法の平面に並べます（範囲が数百 km を超えて端のセルが 0.1% 以上大きくなるときは知らせます）。「投影法」では選んだ座標系（平面直角座標系・UTM・任意の EPSG コード）の平面にその単位（経緯度なら度・分・秒）で並べ、結果もその座標系で書き出されます。範囲の端のセルは、形を保って残す・範囲の形で切り取る・中心が範囲内のものだけ・範囲に収まるものだけから選べます。「詳細設定」では大きさを辺の長さ・幅（向かい合う辺の間）・面積のどれで決めるか、回転（時計回りの角度）、六角形の向き（辺が上・角が上）、格子の基準（範囲の左下・範囲の中心・座標系の原点・指定した点。原点や点を基準にすると別の範囲の格子とも継ぎ目が揃います）、範囲を外接する四角にする、レイヤー名、セルの上限（既定 20 万）を選べます。各セルには id・行・列・ラベル（左上から `A1`, `B1`…）・楕円体上の面積（m²）が付きます。スクリプトからは `viewer.tool('tessellate', { shape: 'hexagon', size: 500, area: 'view' })` のように使えます
- **スクリプト**: 「ツール」→「スクリプト…」で、ArcGIS の arcpy のように JavaScript で解析や編集を書いて実行できます。サンプル（面積の計算、属性の一括変更、ポリゴン内の点の数、バッファ、撮像計画の CSV、GeoJSON・CSV の書き出し、画像の統計、正規化差の画像、画像の見え方をそろえる、すべての画像で NDVI、属性で色分け）を選んで「実行」（Ctrl+Enter）するだけで試せ、`viewer.` や `geo.` と打つと関数の候補（引数と説明つき）が、`viewer.features('` の中ではレイヤー名の候補が出ます（Ctrl+Space でも）。使える関数は「使える関数」に一覧があります。
  - `viewer.*`: レイヤーの一覧、地物の読み取り（GeoJSON・経緯度、範囲・選択中のみ・件数で絞り込み）、選択、地物の追加・変更・削除、一時レイヤーの作成、プロセッシングのツール（バッファ・重心・ポイント→ライン・ボロノイ）、撮像計画の計算（結果をレイヤーにも）、画像の大きさ・画素値・地点の値の読み取りと新しい GeoTIFF の作成、GeoJSON・CSV・Shapefile・GeoPackage とテキスト（.csv・.json など）の保存、地図の移動
  - 画面でできる大抵の操作も `viewer.*` で自動化できます。レイヤーの表示・不透明度・重ね順・閉じる、画像の補正（明るさ・コントラスト・自動ストレッチなど）・バンドの割り当て・ノーデータ・着色、ベクターのスタイル（単一・分類・段階、ラベル）、地図の中心・ズーム・範囲、背景地図、ブックマーク、タイムラインの期間、並べて比較・スワイプ・3D・テーマ、メニューのボタン（`viewer.command('timeline-open')` など）。
  - `viewer.tool('band-math', { image: レイヤー, preset: 'ndvi' })` のように、プロセッシングのツール（バッファなどのベクター処理、バンド演算・変化抽出・土地被覆分類・位置合わせ・RGB 合成・モザイク・パンシャープン、表示範囲の保存）を、ダイアログの項目を名前で指定して実行でき、できたレイヤーが返ります。項目と選べる値は `viewer.toolOptions('band-math')` で分かります。ツール名やメニュー名も `viewer.tool('` の中で候補が出ます。
  - `viewer.open(url, { type })` で COG・ファイル・WMS・WMTS・WFS・Esri を URL から開けます。ビューアがまだ使っていないサーバーには、実行ごとに 1 回「接続してよいか」の確認が出ます（スクリプトが勝手に外へデータを送らないため）。`viewer.openFiles()` はスクリプトのパネルに「ファイルを選ぶ…」を出し、自分で選んだファイルだけを開きます。未保存の変更があるレイヤーは閉じません。
  - `geo.*`: 測地線（WGS 84 楕円体）の面積・長さ・距離・方位角、バッファ、重心、単純化、結合・重なり・差、位置関係（含む・交わる…）、座標系の変換
  - 安全のため、スクリプトはページから切り離された環境（オリジンを持たない sandbox iframe の中の Web Worker、通信をすべて禁じる CSP つき）で動きます。画面・通信・Esri のトークン・ブラウザ内の保存領域には触れられず、ビューアが用意した関数だけを呼べます。関数は渡された値を確かめ、サービスの URL やトークンは返しません。「停止」でいつでも打ち切れ、無限ループでもページは固まりません。
  - 地物の追加・変更・削除はふつうの編集と同じく編集バーの未保存の変更に入り、保存するまでサーバーやファイルには書き込まれません。1 回の実行での変更は「元に戻す」1 回で取り消せます。`viewer.saveEdits()` で保存もできますが、そのたびに件数と保存先を示して確認します。
  - スクリプトは自分で「実行」を押したときだけ動きます（プロジェクトファイルやリンクから勝手に動くことはありません）。「保存」でこのブラウザに、「…」→「.js に保存」でファイルにできます。
- **サーバ処理（ArcGIS GP・OGC API – Processes）**: 「ツール」→「サーバ処理…」で、ArcGIS の GP サービス（`…/GPServer` を入れるとタスクの一覧、`…/GPServer/タスク名` ならそのタスク）や OGC API – Processes（ランディングページ・`…/processes`・`…/processes/{id}`）の処理をサーバーで実行します。`config.json` の `gpServices` に書いたサービスは「サービス」から選べます（下記）。タスクの引数から入力欄を自動で作り、必須の引数だけを表に出して、任意の引数は「詳細」にたたみます（既定値はサーバーのもの）。文字列（候補があれば選択）・整数・実数・真偽・日時・距離と単位（GPLinearUnit）・URL（GPRasterDataLayer・GPDataFile）・複数値（カンマ区切り）・JSON と、地物（GPFeatureRecordSetLayer、OGC は GeoJSON のジオメトリ・地物・FeatureCollection）を入れられます。地物は開いているベクターレイヤー（全件か選択中の地物）か、「地図に描く」で描いた図形を送り、表（GPRecordSet）には CSV などのレイヤーの行を送ります。同期のタスク（`esriExecutionTypeSynchronous`）は `execute` の答えを待ち、非同期のタスクは `submitJob` してジョブの状態とメッセージ（OGC は `Prefer: respond-async` のジョブの状態と進み具合）を表示しながら待ちます。「取り消し」でジョブを取り消せます（Esri は `cancel`、OGC は `DELETE`）。結果の地物（GPFeatureRecordSetLayer・GeoJSON）は属性付きの一時レイヤーとして開き（結果の座標系から地図の投影に変換し、日本の座標系ならその座標系を書き出しの既定にします）、画像（GPRasterDataLayer・画像の URL）は COG（画像）として開き、開けなければリンクを出します。数値・文字などの値とファイルのリンク、サーバーのメッセージは画面の「結果」に出し、ジョブに結果のマップサービスがあれば地図レイヤーとして加えます。トークンは「トークン」欄（または `gpServices` の `token`）に入れます。トークンは Esri には POST の引数で、OGC には `Authorization: Bearer` で、そのサービスと同じホストにだけ送ります。応答は 64 MB・地物は 5 万件までで、http(s) 以外の URL はたどりません。スクリプトからはツール `gp` として使えます
- **単バンド画像の着色**: レイヤー一覧の画像の行の「◐」（ベクターのスタイルと同じボタン）か、「プロセッシング」の処理「単バンド画像の着色」で開くと、白黒・SAR などの 1 バンド画像をカラースケール（赤・緑・青・シアン・マゼンタ・黄・オレンジ・好きな色、熱・ビリディス・虹・青→白→赤）で表示できます。選ぶとすぐ地図に反映され（GPU で描画時に着色するので画像は作りません）、補正パネルの明るさ・コントラストはそのまま使えます。「反転」「暗い所を透明に」と、下のレイヤーとの重ね方（通常・スクリーン・差・比較（明／暗）・乗算）も選べます。「2 時期を色分けして重ねる」で前と後の画像を選んで「赤とシアンで重ねる」を押すと、前を赤・後をシアンにして後をスクリーンで重ねます。変わらない所は白黒、後で明るくなった所はシアン、暗くなった所は赤になります。着色はレイヤー一覧の色見本で分かり、プロジェクトにも保存され、表示範囲の画像保存にもそのまま写ります
- **ノーデータの透明化**: ファイルのノーデータ値（GDAL_NODATA）と、タグがなくてもよく使われる埋め値（-9999・-32768・浮動小数点の最小値と最大値・NaN）の画素は開いたときから透明です。「プロセッシング」の処理「ノーデータの透明化（黒い縁など）」で、画像ごとに「黒い縁（すべてのバンドが 0 の画素）を透明にする」、ほかに透明にする値（`255, 65535` のようにカンマ区切り）、自動の値を使わない（ファイルがノーデータとしている値もそのまま表示）を選べます。すべてのバンドがこれらの値の画素が透明になり、DRA の統計からも外れます。値は 16 bit・浮動小数点の画像なら元の値、8 bit の画像なら 0〜255 で書きます。設定はプロジェクトに保存され、`config.json` の `imageRules` の `noData` でファイル名ごとの既定にもできます
- **投影の設定**: 投影の情報がない画像（PNG・JPEG などの画像、座標のない TIFF、座標はあっても座標系（GeoKeys）のない TIFF）は、地図の原点付近に置かれ、レイヤーの行に ⌖ ボタンが出ます。⌖ か「プロセッシング」の「投影を設定（座標系・ワールドファイル・四隅）」で、座標系（EPSG コード。JGD2011 の経緯度・平面直角座標系 I〜XIX 系・UTM、WGS 84 の UTM は候補から選べ、ほかのコードは `config.json` の `projectionLookup` から定義を取ります。WKT も貼り付けられます）と配置を設定します。配置は、ワールドファイル（`.tfw`・`.jgw`・`.pgw`・`.wld` など、GDAL の `.aux.xml` も可）、範囲（左・下・右・上）、四隅の座標（3 点以上。回転・ゆがみも可で、回転した画像は描画時にアフィン変換で変形します）、画像の座標をそのまま使う（座標系だけ設定）から選べます。画像と一緒にワールドファイルと `.prj`（または `.aux.xml`）を選ぶと、開いたときからその位置に表示します。ワールドファイルだけのときは座標系を聞くダイアログが開きます（経緯度らしい値なら WGS 84 が入ります。前回の座標系も覚えます）。設定はプロジェクトに保存され、開き直すと同じ位置に戻ります。「投影を外す」で元に戻せます
- **バンド演算・指標**: 「プロセッシング」の処理で「バンド演算・指標」を選ぶと、NDVI・NDWI・NDBI・SAVI・EVI を名前で選んで計算し、1 バンドの画像（32 bit 浮動小数）を新しいレイヤーとして開きます（植生指標は茶→黄→緑で着色）。使うバンドはバンド名（GDAL の DESCRIPTION）から、なければ一般的な並び（青・緑・赤・近赤外）から選ばれ、変えることもできます。詳細設定では `(B4 - B3) / (B4 + B3)` のような式を自由に書けます（B1〜Bn、+ − * / ^、比較、abs・sqrt・exp・ln・log10・min・max・clamp・if）。0 で割った所やノーデータの所は値なしになり、結果は GeoTIFF で保存できます
- **変化抽出（2 時期）**: 「プロセッシング」の処理で「変化抽出」を選ぶと、同じ場所の前・後の画像（バンド）を 1 つの格子にそろえて画素ごとに比べ、値が下がった所を青、上がった所を赤（変化なしが白）で塗った 1 バンドの画像（32 bit 浮動小数）を新しいレイヤーとして開きます。比べ方は差（後 − 前）・対数比 dB（SAR 向け）・比・正規化差。大きく変わった所は「変化域」の一時レイヤーにポリゴンで出し、方向（増加・減少）・面積（m²）・画素数を属性に持ちます。しきい値は既定で変化の平均 ± 標準偏差の 2 倍、詳細設定で値・向き・最小の大きさ・再サンプリングを変えられます。結果は GeoTIFF で保存できます
- **自動位置合わせ**: 「プロセッシング」の処理で「自動位置合わせ」を選ぶと、合わせる画像と基準の画像の模様を照合（位相相関）して、ずれを自動で求めます。重なる範囲全体を粗く照合してから、格子状の数か所（既定 4 × 4）を基準の画像の解像度で照合してタイポイントにし、平行移動（中央値）かアフィン（回転・伸縮も、最小二乗、外れ値は除外）で直します。結果は基準の画像と同じ格子に載せた、すべてのバンドを持つ新しいレイヤーとして開き、ずれ（東・北）・照合できた数・残差をステータスに出します。明るさの違う画像どうし（別の日、別のセンサー）でも照合できますが、模様の少ない画像（水面など）は照合できません。結果は GeoTIFF で保存できます
- **RGB 合成**: 「プロセッシング」の処理で「RGB 合成」を選ぶと、開いている画像のバンドを赤・緑・青に 1 つずつ割り当てて 1 枚の 3 バンド画像を作ります。1 バンド画像が 2 枚なら古い方（撮影日時が分からなければ一覧の下の方）が赤、新しい方が緑と青（シアン）に自動で入ります。画像の格子・座標系・解像度は違ってよく、詳細設定の「基準の画像」（既定は一番細かい画像）の格子にそろえて、重なる範囲（または全体）を作ります。センサーモデルで置いた画像（ICEYE など）が基準のときは Web メルカトルで作ります。値はそれぞれの画像の値のまま（型が違うときは 32 bit 浮動小数）なので、DRA などの補正もバンドごとに効きます。結果のレイヤーを選んで同じ画面を開くと GeoTIFF で保存できます
- **モザイク**: 「プロセッシング」の処理で「モザイク」を選ぶと、開いている画像（隣り合う画像や、古い画像の上に新しい画像など）をつなぎ合わせて 1 枚にします。重なる所は優先順の上の画像の値を使い、データのない所（nodata・NaN・画像の外、既定では全バンド 0 の黒い縁も）は次の画像で埋めます。優先順はレイヤーの順・新しい画像を優先・古い画像を優先から選べ、一覧のチェックで使う画像を選びます。「境界をぼかしてつなぐ」で、上の画像の端（とデータのない所の手前）を下の画像へなめらかに溶け込ませます（幅は詳細設定、既定 32 px。下に何もない所はぼかしません）。詳細設定では重なる所を平均にする・基準の画像（既定は一番細かい画像）・範囲（既定はすべてを含む範囲）・再サンプリングも選べます。格子・座標系の違う画像も RGB 合成と同じようにそろえ、値は元の型のまま（型が違えば 32 bit 浮動小数）、バンド数が違えば少ない方に合わせます。結果は新しいレイヤーで開き、同じ画面から GeoTIFF で保存できます
- **パンシャープン**: 「プロセッシング」の処理で「パンシャープン」を選ぶと専用の画面が開きます。パンクロ画像（高解像度の 1 バンド）とマルチスペクトル画像（カラー）は開いている画像から自動で選ばれ、手法（Gram-Schmidt〔おすすめ〕・IHS・Brovey）を選んで「実行」するだけです。再サンプリング・強さ・輝度の重みは「詳細設定」にあります。2 つの画像は別ファイル・別解像度でよく、同じ座標系で重なっている部分を、パンクロの解像度・マルチスペクトルのバンド数と値の型のまま新しいレイヤー「〜_pansharpen.tif」にします（バンド割当と補正はマルチスペクトル画像から引き継ぎ）。結果のレイヤーを選んで同じ画面を開くと GeoTIFF で保存できます。位置情報のない普通の画像どうしは、同じ範囲を写したものとして重ねます。とても大きい場合（約 5,000 万画素 × 3 バンド超）は縮小して作ります
- **AI（物体検出・クリックで抽出）**: 「ツール」→「AI」で、外で学習して ONNX に書き出したモデルをブラウザの中で動かします（[ONNX Runtime Web](https://onnxruntime.ai/docs/get-started/with-javascript/web.html)。WebGPU があれば GPU、なければ CPU〔WebAssembly〕）。モデルは `config.json` の `aiModels`（URL。閉域なら社内サーバーに置けます）か、「ファイルから選ぶ…」でパソコンの .onnx を選びます。画像はサーバーに送りません
  - **サンプルのモデル**: `aiModels` を書かなければ、ビルドに入っている 3 つが並びます（閉域でも動きます。詳しくは `public/models/README.md`）。物体検出は YOLO11s-OBB（DOTA で学習。飛行機・船・大型車両・小型車両・貯蔵タンク・港・橋など 15 クラスを回転矩形で。AGPL-3.0 なので、ビューアごと社外に配布・公開するときは注意）と YOLOX-Tiny（COCO の 80 クラス。地上の写真向け。Apache-2.0）、クリックで抽出は MobileSAM（Apache-2.0）です。初めて使うときに読み込み（合わせて約 90 MB）、以後はキャッシュから使います
  - **物体検出…**: YOLO（Ultralytics の YOLOv5・v8・v11 以降、NMS 込みの end-to-end 書き出し）か YOLOX で、選択中の画像（なければ一番上の表示中の画像。WMS なども可）の表示範囲を、補正をかけた見た目のまま解析します。表示範囲をモデルの入力サイズのタイル（既定で 20% 重ねる）に分けて順に推論し、タイルの境目で重なった検出は NMS（クラスごと。小さな切れ端が大きな枠に収まるものも除く）でまとめます。結果はクラス・スコア付きのポリゴンの一時レイヤーになります（スタイルの「属性で色分け」でクラスごとに塗り分けられます）。Detectron2 で学習した Faster R-CNN などを `export_model.py --format onnx --export-method tracing` で書き出した ONNX（入力は 1 枚の画像 [3, 高さ, 幅]、出力は boxes・classes・scores）も、出力の形で見分けてそのまま動きます（入力の大きさはモデルの固定サイズ、0〜255 の B・G・R を渡し、NMS はモデルの中のものを使います。スコアのしきい値の既定は 0.5。Detectron2 は既定で 1 枚 100 件までしか出さないので、100 件に届いたタイルは少し重ねた 4 つに分けて（同じ縮尺のまま）解析し直します（2 段まで。書き出し時に `cfg.TEST.DETECTIONS_PER_IMAGE = -1` にすれば上限はなくなり、そのときは config.json に `"maxDetections": 0`。別の上限で書き出したらその数）。クラス名は config.json の `classes` か、ONNX のメタデータ `names` に `{0: 'plane', 1: 'heli'}` の形で）。矩形のほか、回転矩形（OBB。DOTA で学習した YOLOv8-OBB なら飛行機・船・車両・タンクなど）とインスタンスセグメンテーション（輪郭のポリゴン）に対応します。Ultralytics の ONNX はクラス名・入力サイズ・種類をモデル自身が持っているので、選ぶだけで使えます。表示の細かさで解析するので、小さな物体は拡大するか、詳細設定の「解析の細かさ」（2・4・8・16 倍）を上げてください（8 倍以上の大きな画像は、ブロックに分けて描いては解析するので、メモリは増えませんが時間はかかります）。詳細設定にはスコアのしきい値・重なりの判定（IoU）・タイルの重なり・検出するクラスの絞り込みもあります。実行するとダイアログは閉じ、地図の下に進み具合と「中止」が出ます。検出はバックグラウンドで進むので、その間も地図を動かしたり別の作業をしたりできます（解析範囲は実行した時点の表示範囲です）。推論は Web Worker で動きます。GPU（WebGPU）がなければ CPU で、ページがクロスオリジン分離されていれば（Service Worker 経由で開いたとき。下の PWA を参照）1 つのモデルを複数のスレッドで動かし（4 コアなら 3 スレッド、8 コア以上は 2 ワーカー × 3〜4 スレッド。コアを 1 つページ用に残します）、そうでなければ 1 スレッドのワーカーをコア数の半分（最大 3 つ）並べてタイルを並行に処理します。4 コアの CPU で測ると、マルチスレッドの方が YOLOX-Tiny（×4、30 タイル）で 13.3 → 9.7 秒、YOLO11-OBB（×2、3 タイル）で 12.3 → 7.3 秒、Faster R-CNN R50-FPN（600×600、4 タイル）で 28.6 → 19.0 秒と速く、解析中に画面が止まる時間も短くなります（スレッド数は詳細設定の上のモデル情報に出ます）。画像は画面とは別の隠れた地図に描き、ブロックに分けるときは次のブロックを描くのと前のブロックの解析を重ねて進めます
  - **クリックで抽出**: Segment Anything（SAM・MobileSAM・EfficientSAM など、segment-anything の `export_onnx_model.py` と同じ入出力のエンコーダーとデコーダー）で、画像の物体をクリックするとその輪郭をポリゴンにします。Shift+クリックで範囲を広げ、Alt+クリックで除き、「1 つ戻す」で取り消せます。表示が変わらない間は画像の解析（エンコーダー）を使い回すので、2 回目からのクリックはすぐです。「レイヤーにする」で一時レイヤーにし、Esc か「終了」で終わります。ファイルから選ぶときはエンコーダーとデコーダーの 2 つを一緒に選びます（名前に encoder・decoder があればそれで、なければ大きい方をエンコーダーとみなします）
  - **結果の属性**: どちらの結果にも、画像のファイル名・画像ID（「画像カタログ」から開いた画像のとき）・撮像日時（タイムラインと同じ求め方）・モデル・検出日時・備考が付きます。結果のレイヤーは ✎ で直せます（輪郭の修正、クラスの書き換え、誤検出の削除、見逃しの追加）
  - **DB へ転記…**: `config.json` の `detectionOutputs` に転記先（Esri フィーチャーサービスのポリゴンかポイントのレイヤー）と属性の対応を書くと出ます。AI の結果のレイヤー（全件か選択中の地物）を、役割ごとの属性名に合わせて書き込みます。地物ごとに、モデルが出したままか（AI）・人が輪郭かクラスを直したか（修正）・人が描き足したか（手動）を判定して「状態」に書きます。転記した地物はレイヤーが覚えているので、もう一度転記すると、新しい地物は追加、転記後に直した地物はその行を更新、変わらない地物は送りません（一時レイヤーはブラウザに保存されるので、再読み込みしても続きから転記できます。転記後に消した地物は DB からは消しません）。ポイントのレイヤーへは輪郭の内側の点を書きます。転記先にない属性は書かずに知らせます。日時は転記先の日付型に、数値・文字は属性の型と長さに合わせます
  - ブラウザでは学習はせず、推論だけを行います。目安は、YOLO の n・s 級なら 1 タイル数十〜数百ミリ秒（GPU）で、SAM の ViT-B のような大きなエンコーダーは CPU だと 1 枚に数十秒かかるので、GPU がない環境では MobileSAM などの軽いモデルをおすすめします。ONNX Runtime の WebAssembly（約 27 MB）はサイトに同梱し、初めて AI を使うときに読み込みます（PWA では使ったときにオフライン用に保存します）
  - **XY 座標からポイントを作成**: CSV などの表の X・Y の列からポイントを作ります（列は「経度」「lon」「x」などの名前から推測します）。値の座標系は WGS 84 のほか、平面直角座標系なども選べます（X が東向き、Y が北向き）。数値でない行や範囲外の行は飛ばして件数を出します。属性は行のまま引き継ぎます
  - **測地線バッファ**: WGS 84 楕円体上の距離で点・線・面を広げます（負の距離で面を縮めます）。点は GeographicLib で測地線の円そのものを作り、線と面は地物ごとの正距方位図法（中心からの距離が正確）で JSTS のバッファをかけます。線の端の形と、結果を 1 つに融合（ディゾルブ）を選べます
  - **ポイント→ライン**: 点を属性（時刻・数値・文字）で並べ替えてラインにします。属性を選ぶと値ごとに別のラインにします（車両ごとの軌跡など）。ラインには開始・終了の値、点の数、測地線の長さ（m）が入ります
  - **ポリゴンの重心**: 地物ごとの正距方位図法で求めるので、高緯度でも Web メルカトルに引っ張られません。パートごとの重心、重心が形の外に出るときは内側の点にする指定ができます
  - **ボロノイ分割・ティーセンポリゴン**: 同じ分割で、ボロノイは id だけ、ティーセンは点の属性を引き継ぎます。ティーセンはポリゴンレイヤー（行政界など）で切り抜けます。範囲は点の範囲に余白（%）を足したものです
  - **ベクター投影変換**: 一時レイヤーの座標系を変えます（書き出しの既定の座標系になります）。WGS 84・JGD2011・JGD2000・日本測地系（Tokyo）・平面直角座標系 I〜XIX 系・UTM はオフラインでも使え、それ以外は EPSG コードで `projectionLookup` から定義を取得します
- **Esri の編集**: 編集できる Esri レイヤーには一覧に ✎（編集）ボタンが出ます。押すと地図の上に編集ツールバーが出て、サービスが許可している操作だけ使えます
  - **追加**: 地図をクリック（ラインとポリゴンは頂点をクリックし、ダブルクリックか Enter で終了。途中は Backspace か Ctrl+Z で 1 点戻し、Esc でやめます）。ポリゴンのレイヤーでは「矩形」（角を 2 回クリック）「円」「正多角形」（中心と半径の 2 回クリック）も選べます。テンプレートの初期値が入り、属性テーブルの「選択中のみ」で属性を入力できます
  - **形状編集**: 頂点や辺をドラッグして形を変えます（辺をドラッグすると頂点が増え、Alt+クリックで頂点を削除）。選択中の地物はドラッグで移動できます
  - **スナップ**: 描くときと形を変えるときは、表示中のベクターレイヤー（編集中のレイヤーから順に合わせて 2 万件まで）の頂点と辺に吸い付きます（「その他」→「スナップ」で切り替え）
  - **数値入力**（「その他」→「数値入力」）: 描くときに編集バーの下へ入力欄を出します。頂点は座標（緯度経度・MGRS・UTM、または座標系を選んで平面直角座標系 I〜XIX 系・UTM・Web メルカトル・EPSG コードの X / Y。平面直角座標系は測量と同じく X が北、Y が東。`X, Y` と貼り付けると両方に入ります）か、直前の頂点からの長さ（m）と方位（北から時計回りの度）で置き、描いている辺の長さと方位も表示します。矩形は角の座標と幅・高さ（m）・回転角、円は中心と半径、正多角形は中心・半径・辺の数・最初の頂点の方位で作ります（地図で最初にクリックした角・中心も入ります）。長さは楕円体上の距離です
  - **その他**: 「複製」（選んだ地物を同じ位置に複製。ほかのレイヤーの地物も、図形の種類が合えば同じ名前の属性ごとこのレイヤーに写せます）、「移動…」（東・北へ何 m か、または中心を座標へ）、「回転…」（中心のまわりに時計回りに何度）、「平行線…」（線は左が正・右が負、面は外側が正・内側が負の距離で、平行な線や面を新しく作ります）、「分割」（選んだ線か面を、地図に描いた線で切り分け。元の属性が写ります）、「結合」（選んだ地物を 1 つにまとめ、属性は最初の地物のもの）
  - **削除**: 地図か属性テーブルで選んだ地物を削除します
  - **属性**: 編集中は属性テーブルのセルが入力欄になります。コード値ドメインはプルダウン、範囲ドメイン・文字数・型はサーバーの定義に合わせて確認します。OBJECTID や編集者情報など、サーバーが管理する項目は変更できません
  - **保存**: 変更は「保存」を押すまでサーバーに送られません（`applyEdits` でまとめて送信）。保存前は「元に戻す」（Ctrl+Z）で 1 つずつ取り消し、「やり直し」（Ctrl+Y）で戻せ、「破棄」でまとめて取り消せます。未保存のセルは色付き、追加した行は左端に緑の線が付きます。サーバーが受け付けなかった地物は赤く表示し、理由を状態欄に出します。未保存の変更があるままページを閉じようとすると確認が出ます
- **共有リンク**: 追加したサービスのレイヤーと背景地図は URL の `?service=`・`?base=` に入るので、そのリンクを開くと同じ表示になります。表示範囲（中心・ズーム・回転）もアドレスの `#view=緯度,経度,ズーム,回転` に入るので、リンクを開くと同じ場所が表示されます。ヘッダーの「ブックマーク」→「リンクをコピー」でそのままコピーできます（ローカルファイルのレイヤーはリンクに含まれません）
- **リンクで図形を表示**: 外部のシステムやメールから、緯度経度・MGRS・WKT を書いたリンクで開くと、その点・線・面を一時レイヤーとして追加し、そこへズームします（一度追加するとアドレスから消え、再読み込みしても一時レイヤーとして 1 回だけ復元されます）
  - `?geom=35.6812,139.7671` 点（座標入力欄と同じ表記: 緯度経度・度分秒・`北緯35度40分…`・MGRS `54SUE8843349290`・UTM）。`geom=A;B;C` で複数の点
  - `?geom=POLYGON((139.70 35.65, 139.80 35.65, 139.80 35.72, 139.70 35.65))` WKT（経度・緯度の順。`SRID=3857;` を付けた EWKT も可）。`?line=A;B;C`・`?polygon=A;B;C` は頂点を `;` 区切りの座標で（ポリゴンは自動で閉じます）。`?geojson=` に GeoJSON（ジオメトリ・Feature・FeatureCollection。単純な属性は属性に入ります）
  - `label=`（n 番目の図形パラメーターに n 番目のラベル）、`name=` レイヤー名、`color=#e6194b` 色、`zoom=` 点だけのときのズーム（既定は 14。点だけなら離れていても 14 より寄りません）。`#view=` があればその表示範囲を優先します。各パラメーターは複数指定できます
  - 例: `…/index.html?geom=35.6812,139.7671&label=東京駅&polygon=35.65,139.70;35.65,139.80;35.72,139.80&name=現場`
  - 安全のため値はデータとしてだけ読み、厳しく検査します（WKT に使える文字のみ、1 値 20 万文字・図形 1000 個・頂点 10 万点まで、緯度経度の範囲）。読めなかった値は理由を状態欄に出し、残りは表示します
  - インストールしたアプリ（PWA）は `web+imageviewer:geom=35.68,139.76&label=駅` のリンクも受け取ります。アプリが開いていれば今のウィンドウに図形を追加します（`launch_handler`）
  - 属性テーブルの行の右クリック →「図形のリンクをコピー」で、選んだ地物を表示するリンク（WKT）をコピーできます（ラベル表示中の属性がラベルになります）
- **クリップボード・共有**（「ツール」→「クリップボード・共有」）
  - **貼り付け**: 地図の上（入力欄の外）で Ctrl+V か「クリップボードから貼り付け」で、GeoJSON（ジオメトリ・Feature・FeatureCollection）・WKT／EWKT（1 行に 1 つ）・KML（Placemark だけでも可）・座標（1 行に 1 点、座標入力欄と同じ表記）・図形を表示するリンク・Excel からコピーした表（タブ区切りか CSV。緯度・経度の列、WKT の列、または X・Y の列）を一時レイヤー「貼り付け」に追加し、そこへズームします。何として読んだかを地図の上に短く表示し、読めないときは理由を出します。X・Y の列の表は列と座標系（平面直角座標系など）を尋ねます。上限はリンクの図形と同じです（20 万文字・図形 1000 個・頂点 10 万点）
  - スクリーンショットなどの画像を貼り付けると、位置情報のない画像として開きます。図形のない URL を貼り付けると、COG として開くかを尋ねます（勝手には開きません）
  - **コピー**: 属性テーブルの行の右クリック →「GeoJSON でコピー」「WKT でコピー」（WGS 84、小数 7 桁）。地図の上で Ctrl+C を押すと、選択中の地物を GeoJSON でコピーします。「表示範囲の画像をコピー」で地図を PNG 画像としてコピーします（2D 表示のみ）
  - **共有…**: 共有に対応したブラウザ（スマートフォンなど）では、今の表示のリンク（`#view=`）と表示範囲の画像を他のアプリに送れます
  - インストールしたアプリ（PWA）は OS の共有メニューの送り先になります（manifest の `share_target`）。共有された画像・GeoTIFF・KML／KMZ・GPX・GeoJSON・Shapefile（.zip）・プロジェクトはファイルを選んだときと同じように開き、文字・URL は貼り付けと同じように読みます（Service Worker がブラウザ内に一時保存し、`?share=` で開いたページが 1 回だけ受け取って消します）
- **ブックマーク**: ヘッダーの「ブックマーク」→「現在の表示を追加」（キー M）で、今の表示範囲・回転・各レイヤーの表示／非表示を名前を付けて残し、一覧のクリックでその表示に戻ります（同じ名前のレイヤーだけ表示を切り替えます）。✎ で名前の変更、× で削除。ブックマークはブラウザに残り、プロジェクトにも保存されます（開いたプロジェクトのブックマークは一覧に加わります）
- **注記**: 「ツール」→「注記を描く」（キー N）で地図の上に注記の道具が出ます。矢印・線（クリックで点を置き、ダブルクリックで終わり）・四角（2 か所のクリック）・文字（クリックした所に入力して Enter）を、色と大きさ（小・中・大）を選んで描けます。「選択・移動」でクリックして選び、ドラッグで動かし、Delete で削除。色・大きさは選んだ注記にも効きます。注記はブラウザに残り、プロジェクトにも保存され、印刷レイアウトにも入ります
- **印刷レイアウト**: 「ツール」→「印刷レイアウト…」で、今の表示範囲を A4・A3（縦・横）の用紙いっぱいに描き直し、タイトル・縮尺バー・方位記号（回転していればその向き）・凡例（表示中のレイヤー、色スケールはその色の帯）・下の注記・縮尺と日付・出典を付けて PDF か PNG で保存します。解像度は 150・200・300 dpi
- **保存先（フォルダへ直接書く）**: 「ツール」→「保存先…」で「フォルダを選ぶ…」と、処理結果の GeoTIFF（バンド演算・変化抽出・分類・位置合わせ・RGB 合成・モザイク・パンシャープン・オルソ）、表示範囲の保存、印刷レイアウト、3D の画像を、ダウンロードせずにそのフォルダへ直接書きます（Chrome・Edge。File System Access API）。フォルダはブラウザに残り、再読み込み後は書き込みの許可だけ聞きます。同じ名前のファイルがあれば「(1)」「(2)」を付け、書けないとき（フォルダが消えた・許可しなかった）はダウンロードに切り替えて理由を状態欄に出します。「ダウンロードに戻す」で元に戻ります。速さはダウンロードとほぼ同じで（256 MB で 0.4–0.9 秒、どちらも同程度）、得なのはダウンロードフォルダから移す手間と保存ダイアログがなくなることです。対応しないブラウザではメニューに出ず、ダウンロードで保存します
- **処理結果の保存（COG・ブラウザ内保持）**: プロセッシングの結果（バンド演算・変化抽出・分類・位置合わせ・RGB 合成・モザイク・パンシャープン・オルソ）は、作りながらタイルのまとまりごとにブラウザ内のストレージ（OPFS）へ直接書くので、何 GB の結果でもページの中に一つの大きな Blob を作りません。再読み込みしても残り、「ツール」→「処理結果…」で一覧・開く・保存・削除ができます（使用量とブラウザの空きも表示）。結果のレイヤー行の「⇩」（右クリックメニューにも）で保存すると、既定は COG（256 px タイル、半分ずつの概要画像を 1 タイルまで、Deflate＋予測子で圧縮、GDAL と同じ並び＝ディレクトリが先頭・小さい概要画像から）で、QGIS・GDAL・Web 地図で速く開けます。「GeoTIFF（作ったまま・圧縮なし）」ならすぐ保存できます。詳細設定で圧縮なし・概要画像の作り方（平均／最近傍＝分類向け）・概要画像なしを選べ、地図で動かしたレイヤーは動かした位置で保存します。分類は番号の GeoTIFF とクラス表 CSV も一緒に保存します。保存先フォルダを選んでいれば COG はそのフォルダのファイルへ直接書きます。プロジェクトに入れた処理結果は、プロジェクトを開き直すとブラウザ内のものが開きます。ブラウザの空きが足りないとき（や OPFS がないブラウザ）は従来どおりページの中だけに置きます。
- **大量の地物**: 地物が 5,000 件を超えるベクターレイヤーは、GPU（WebGL）で点・線・面を描くので、数万件でも地図を動かしたときに引っかかりません。ラベルはこれまでどおり重なりを間引いて描きます。GPU が使えないブラウザ（ソフトウェア描画になる環境）や「サービスの表示のまま」のレイヤーは従来の描き方のままです。`?vectorgl=always` で件数によらず GPU、`?vectorgl=never` で常に従来の描き方にできます
- **ポイント**: ヘッダーの「ポイント追加」を押してから、選択中の画像をクリックするとポイントを置けます。名称は左の一覧で編集でき、ポイントはドラッグで動かせます。「GeoJSON 保存」で全ポイントを `points.geojson` に保存します。属性は `image`（画像ファイル名、拡張子なし）と `name`（ポイント名称）です。座標は、GeoTIFF の点が経緯度（WGS 84）、普通の画像の点が画素座標（左上原点、x は右、y は下向き）です。画像を閉じると、その画像のポイントも消えます
- **距離・面積を測る**: ヘッダーの「距離を測る」「面積を測る」を押して、地図をクリックで点（頂点）を置き、ダブルクリックで終わります。距離は WGS 84 楕円体上の測地線の長さ、面積は楕円体上の面積で、[GeographicLib](https://geographiclib.sourceforge.io/)（Karney のアルゴリズム）で計算します。turf の `distance`・`area` は地球を球とみなすので最大 0.5% ほどずれますが、こちらは楕円体の測地線そのものを計算します（誤差はナノメートル程度）。線も測地線に沿って描くので、長い線は地図の上で曲がって見えます。計測結果は「計測を消去」まで地図に残ります。Esc で描いている途中の計測を取り消せます。選択中のレイヤーが普通の画像（位置情報なし）のときは、その画像の画素数（px・px²）で測ります
- **影から高さを測る**: 「ツール」の「影から高さ」（H）で、建物・塔・木などの根元をクリックし、次にその影の先端をクリックすると、影の長さ × tan（太陽高度）で高さを出します。根元も影の先端も地面の点なので、斜めから撮った画像でもオルソ補正済みなら影の長さは変わりません（地面は平らとみなします）。太陽高度と方位は、画像のメタデータ（GDAL メタデータの `SUN_ELEVATION`・`SUN_AZIMUTH`、Maxar の `MEANSUNEL`・`MEANSUNAZ`、太陽天頂角、NITF の USE00A など）があればそれを、なければ撮影日時（メタデータ・NITF・ファイル名・TIFF の DateTime）と根元の位置から計算し、どちらもなければパネルに入力するか撮影日時（UTC）を入れます。方位が分かるときは影の落ちる向きに案内線を引き、2 点目をその向きに合わせます（「影の向きに合わせる」で切り替え）。測った高さは地図とパネルに残り、「消去」で消えます。位置のない普通の画像では画素数（px）で出します
- **座標のコピー**: 地図を右クリックすると、その地点の座標をコピーするメニューが出ます。緯度経度（`35.681200, 139.767100` のように緯度が先）、MGRS（`54S UE 88433 49290`）、UTM（`54N 388433 3949290` のように帯番号と南北 N/S）、GeoTIFF が別の座標系ならその座標系の座標、画像の上なら画素座標（左上原点）を並べます。普通の画像の上では画素座標だけです。位置のある地点では、その下の「この地点で撮像計画を立てる」で撮像計画を開き、その地点を対象にすぐ計算します
- **カーソル位置の緯度経度**: 地図の上にカーソルがある間、その地点の緯度経度（WGS 84）を地図の左下に小さく出し続けます。地図から出ると消え、位置のない普通の画像の上では出ません。表記（10進・度分秒・MGRS・UTM）は右クリックメニューの下の「左下の表示」で切り替えられ、次に開いたときも同じ表記です
- **座標へ移動**: ヘッダーの入力欄に座標を入れて Enter で、その地点へ移動して印を付けます。緯度経度（10進・度分秒。`35.6812, 139.7671`、`35°40'52"N 139°46'1"E`、`北緯35度40分52秒 東経139度46分1秒`、`35d40m52s`、`354052N 1394601E` のような続け書き、`lat 35.68 lon 139.77`、`POINT(139.77 35.68)`、全角数字や「、」区切りも可。N/S/E/W やラベルがないときは緯度が先ですが、先の値が 90 を超えるときは経度が先とみなします）、MGRS（精度は任意）、UTM（`54N 388433 3949290`）を読めます。地名や住所（`東京駅`、`千代田区丸の内1丁目`）も入れられ、打つ途中で見つかった場所が欄の下に並び、↑↓と Enter かクリックでそこへ移動します（町や建物のように範囲が分かるものはその範囲へズーム）。既定は国土地理院の住所検索で、`config.json` の `geocoders` で Nominatim・ArcGIS のジオコードサービス・Esri の地名レイヤー・地名と緯度経度の CSV に替えたり並べたりできます（下記）。`"geocoders": []` にすると地名は検索せず、入力が外へ送られることはありません
- **幾何補正（左の「幾何補正」欄）**:
  - **標高データ**: DTED のレベル 0・1・2（`.dt0`・`.dt1`・`.dt2`）を開くと、画像ではなく標高データとして扱います。一覧に DEM の印が付き、標高を濃淡で表示します（DRA 付き）。情報欄にはレベル・間隔・標高の範囲・垂直精度を出します。開いている DTED はすべてオルソ補正の地形に使われ、閉じると使われなくなります
  - **標高サービス（ArcGIS）**: 「幾何補正」欄の「標高サービス」（ふだんは折りたたみ）に URL を入れて「追加」すると、ArcGIS のイメージサービス（`…/ImageServer`）を標高データに使います。標高タイルサービス（Terrain3D・TopoBathy3D のような LERC のタイルキャッシュ）はタイルを読み、それ以外の 1 バンドのイメージサービス（WorldElevation/Terrain や自前の DEM）は `exportImage` で 32bit の値を経緯度で読みます。DEM ファイルのように丸ごと読むのではなく、必要な範囲だけその都度読みます: オルソ補正・簡易オルソ補正は画像の範囲、3D の起伏は表示中のタイル、可視解析は観測点の周り。開いている DTED・GeoTIFF の DEM がある所はそちらを優先します。一覧の「表示範囲を取り込む」で、いまの表示範囲の標高を DEM レイヤー（`〜_標高.tif`）にでき、等高線を引けます。地図に開いた 1 バンドのイメージサービスのレイヤーを選んで「標高データとして使う」でも追加できます。認証が必要なサービスは「トークン」に入力します。追加したサービスはプロジェクトに URL で保存され（トークンは保存しません）、`config.json` の `elevationServices` に書くと起動時から使います（下記）
  - **等高線**: DEM を選ぶと「等高線」のチェックが出ます（既定はオフ）。オンにすると DEM のすぐ上に等高線を描き、5 本ごとの太線（計曲線）に標高を表示します。間隔は「自動」（標高の範囲から約 20 本になる 1・2・5 × 10ⁿ m）か 1〜500 m から選べます。線は表示範囲だけを画面の解像度に合わせて Worker で引き直すので、DTED2 でも軽く動きます。DEM を非表示にすると等高線も隠れ、DEM の不透明度を 0 にすると等高線だけになります
  - **オルソ補正**: RPC（有理多項式係数）付きの衛星画像を、開いている標高データの地形で正射投影します。RPC は GeoTIFF の RPC タグ、または一緒に選んだ `.RPB`・`_RPC.TXT` から読みます（画像と同じ名前のもの。画像が 1 枚なら名前が違っても使います）。位置情報のない画像（レベル 1 プロダクト）は、補正前は RPC の基準高でおおよその位置に置きます。「オルソ補正」を押すと、Web メルカトル（EPSG:3857）の新しいレイヤー「〜_ortho.tif」ができます。バンド数と値の型（16bit など）、補正パネルの設定とバンド割当は元の画像から引き継ぎます。DTED の標高（平均海面から）には EGM96 のジオイド高を足して、RPC が使う楕円体高にしています。標高データがない部分は RPC の基準高の平面として補正し、その割合を状態欄に出します。とても大きい画像（約 5,000 万画素 × 3 バンド超）は縮小して補正します
  - **簡易オルソ補正（RPC なし）**: RPC のない、位置情報付きの GeoTIFF（平らな地面に投影済みのもの）も、衛星の方向と標高データで地形の倒れ込みを補正できます。高さ h の地点は、仰角 e の衛星から見ると基準高 h0 との差 (h − h0) / tan(e) だけ衛星と反対側にずれて写るので、その分を戻します。衛星の方位角・仰角は、一緒に選んだ `.IMD`（`meanSatAz`・`meanSatEl`）か GeoTIFF の GDAL メタデータから読み、なければ幾何補正欄に入力します（オフナディア角しかないときは 90° − オフナディア角を仰角にします）。「詳細」では基準高（空欄なら画像の範囲の平均標高）と再サンプリングを変えられます。結果は RPC のオルソ補正と同じ「〜_ortho.tif」のレイヤーで、位置をずらす・保存もそのまま使えます。標高データがない部分は動かしません
  - **位置をずらす**: RPC の位置誤差は手で合わせます。オルソ補正のレイヤーを選んで「位置をずらす」を押すと、地図のドラッグでそのレイヤーが動きます（地図は動きません）。矢印キーで 1 画面画素、Shift + 矢印キーで 10 画素ずつ動かせます。ずらし量は東・北のメートルで表示し、「元に戻す」で元の位置に戻ります。「GeoTIFF 保存」はずらした位置で保存します。Esc か別のレイヤーを選ぶと終わります
  - ジオイド高は `src/egm96.bin`（EGM96 を 0.5° 間隔の格子にしたもの、約 520 kB。オルソ補正を初めて行うときに読み込みます）から補間します。誤差はおおむね 0.1 m、最大でも 3 m 程度です。EGM96 は米国 NGA の公開データで、格子は egm96-universal（MIT）で計算しました
- **情報欄**: 選択中の画像のサイズ・バンド数。GeoTIFF は座標系・解像度・範囲と、ファイルにあればバンド名（GDAL メタデータの DESCRIPTION）も表示します。「メタデータを表示…」で GeoTIFF・COG の詳細（TIFF / BigTIFF、COG かどうか、タイル・圧縮・データ型・nodata、バンドごとの名前と GDAL の統計、GeoKeys・原点・画素の大きさ、GDAL メタデータ、RSET を含む IFD 構成、原画像の TIFF タグ一覧）をダイアログで開き、テキストか JSON でコピーできます。ダウンロードし直さず、開いたときに読んだヘッダーから表示します。サービスのレイヤーは種類・URL・レイヤー名・座標系・地物数・編集できる操作を表示します
- **スワイプ比較**: 情報欄の「スワイプ比較」を押すと、選択中のレイヤーを線の左側だけに表示し、右側には下のレイヤーが見えます（画像同士のほか、ベクターや背景地図とも比べられます）。線はドラッグか、丸いつまみにフォーカスして矢印キー（Shift で大きく）・Home・End で動かせます。つまみのダブルクリックで横線（上側に表示）に切り替わり、Esc で終わります。別のレイヤーを選ぶと、そのレイヤーが比べる対象になります
- **ヒストグラム**: 情報欄の「ヒストグラム」で、選択中の画像（WMS・WMTS も）の表示範囲のヒストグラムを R・G・B（グレー画像は輝度）ごとに表示します。移動・拡大や補正スライダーに合わせて更新され、「補正後」と「補正前」（タイルを読んだままの値）を切り替えられます。「対数」で少ない値も見えるようにでき、グラフを指すとその値の画素数を、下の表にチャンネルごとの最小・平均・中央値・最大を表示します

- **タイムライン**: 「ツール」メニューの「タイムライン」（キー T）で、時間を持つレイヤーを 1 本の時間軸に並べ、期間で絞り込みます。ベクターレイヤーは日時の属性（日付型の属性、`2024-05-01`・`2024/5/1 10:30`・`20240501`・`2024年5月1日` のように日時として読める文字、年の数値、Esri の `timeInfo`）を自動で見つけ、開始と終了の属性があれば期間として扱います。グラフはステップごとの件数をレイヤーごとに積み上げ、画像は撮影日時（GDAL メタデータの取得日時、NITF の IDATIM、ファイル名、TIFF の DateTime の順）を ◆ で、時間次元を持つ WMS は提供時刻を目盛りで示します。グラフをドラッグして期間を選び（端で伸縮、中で移動）、「幅」で 1 時間・1 日・1 週・1 か月・1 年に揃え、⏮ ⏭・矢印キーで送り、▶（Space）で再生します。期間外の地物は地図・3D・属性テーブルから消え、期間外の画像は隠れ（一覧のチェックはそのまま）、WMS は期間の終わりの時刻（それ以前で最新の提供時刻）で描きます。「設定」で累積表示（最初から期間の終わりまで）、再生速度、レイヤーごとの絞り込みの有無・開始と終了の属性・画像の撮影日時の手入力を変えられます。ホイールで時間軸を拡大、ダブルクリックで全期間に戻ります。閉じるとすべて表示に戻ります
- **ダッシュボード**: 「ツール」メニューの「ダッシュボード」（キー B）で、地図の右に開いているレイヤーの概要（種類と表示中の件数）と、ベクターレイヤー 1 つの集計を出します。集計するのは選択中のレイヤー（概要の行か「集計するレイヤー」で固定も可）で、件数（全体・表示範囲内・タイムラインの期間内・絞り込み後・選択中）、属性の値ごとの件数・合計・平均の棒グラフ（値の少ない属性を自動で選び、上位 15 件と「その他」）、数値の属性の分布、時間の推移（タイムラインと同じ時間の属性）を表示します。棒をクリックするとその値の地物だけを地図・3D・属性テーブルに表示し（Ctrl・Shift で複数）、分布の柱で数値の範囲（Shift で広げる）、時間の推移の柱でタイムラインをその期間にします。各グラフはほかの絞り込みが残す地物で数え直し、選んだ値は強調されます。「ヒートマップ」で表示中の地物の密度を地図に重ね（半径を調整可）、「表示範囲内だけ集計」で地図に見えている範囲に限れます。「地物を選択」で絞り込んだ地物を選択にできます（書き出しやプロセッシングで使えます）。左端をドラッグすると幅を変えられます。閉じると絞り込みは解除されます
- **3D 表示**: ヘッダーの「3D」（キー 3）で、地図を WGS 84 楕円体の地球儀（[CesiumJS](https://cesium.com/platform/cesiumjs/)）に切り替えます。もう一度押すと、カメラが見ていた場所の 2D 表示に戻ります。CesiumJS とその地球全体の背景画像（Natural Earth II）はサイトに同梱しているので、閉域・オフラインでも動きます（3D を初めて開いたときに読み込みます。約 1 MB〔gzip〕）。左に「3D」欄が出ます
  - **2D のレイヤーをそのまま地表に**: 画像（補正・DRA・バンド割当込み）、サービス、ベクター（スタイル・ラベル込み）、背景地図、計測・ポイント・選択の強調まで、2D の地図が描くものをそのままタイルにして地球儀に貼ります。2D 側で補正やスタイル、表示・不透明度を変えると 3D にも反映されます。3D 表示中は、2D の表示範囲を使う道具（ポイント追加・スワイプ比較・ヒストグラム）はお休みし、「距離を測る」「面積を測る」「表示範囲を保存」は 3D 用に切り替わります。「プロジェクト」の保存はカメラが見ている範囲と 3D の状態（開いていたか、カメラ、地形・高さの強調・高さの基準・背景、URL の 3D タイル）を保存し、開くと 3D のまま戻ります
  - **DEM の立ち上げ**: 開いている DTED と、標高データにした GeoTIFF、標高サービスで起伏を付けます（標高 + EGM96 ジオイド高 = 楕円体高。DEM のない所は平均海面）。「高さの強調」で起伏を 1〜10 倍にできます（マルチパッチも一緒に伸びます）
  - **GeoTIFF の DEM**: 1 バンドの GeoTIFF（座標系は何でも。UTM・平面直角など）を選び、「幾何補正」欄の「標高データとして使う」を押すと、値を標高（m、平均海面から）として経緯度の格子に再サンプリングし、DTED と同じように 3D の起伏・可視解析・オルソ補正・等高線に使います（最大 1,600 万点）。プロジェクトにも保存されます
  - **マルチパッチ**: マルチパッチ（シェープタイプ 31）の Shapefile を開くと、2D では屋根・床の外形を、3D では立体（三角形ストリップ・ファン・穴あきリング）を描きます。3D の建物をクリックすると、その地物を選択して属性テーブルに出します。高さは「高さの基準」で、標高（ジオイド高を足す）・地表から（最も低い点を地表に）・楕円体高から選べます。既定（自動）は起伏があれば標高、なければ地表からです
  - **3D タイル**: tileset.json の URL を入れて「追加」すると、3D Tiles（1.0・1.1、b3dm・glTF など）を重ねて表示します。「フォルダから開く…」で、tileset.json のあるフォルダをパソコンから直接開けます（サーバー不要。中の相対参照もそのまま読みます）。同じ欄に Esri のシーンサービス（`…/SceneServer`、I3S の 3D オブジェクト・統合メッシュ、WGS 84 のもの）の URL を入れると、それも重ねて表示します。シーンサービスの高さはジオイド基準なので、同梱の EGM96 で楕円体高に直します（Esri の標高サービスは使わないので閉域でも動きます）。一覧で表示切替・移動・閉じるができます
  - **3D 計測と断面図**: 3D 表示中の「距離を測る」（D）・「面積を測る」（A）、または「3D」欄の「距離・断面」「面積」で、地表・3D タイル・マルチパッチの上をクリックして点を置き、ダブルクリック（右クリック）で終わります（Esc で消去）。距離は斜距離・水平距離（楕円体上）・高低差を、面積は水平面積と周長を出します。2 点以上の距離では断面図（標高データの地面、建物などの表面、2 点のときは始点から終点への視線。地球の丸みと大気差込み）を描き、見通しの可否と遮られる距離を出します。断面は CSV で保存できます
  - **3D の画像保存**: 3D 表示中の「表示範囲を保存」か「3D」欄の「画像として保存（PNG）」で、いまの 3D 表示を PNG にします
  - **可視解析**: 観測者の高さ・対象の高さ・半径を決めて「観測点をクリック」を押し、地球儀をクリックすると、その地点から見える範囲（緑）と見えない範囲（赤）を求めます。DTED の全点について観測点からの視線を 1 点ずつ辿り（R3 法）、距離は WGS 84 楕円体上、地球の丸みと大気の屈折（大気差係数、既定 0.13）を考慮します。「建物（マルチパッチ・3D タイル）も遮る」（既定でオン）で、表示中のマルチパッチの屋根の高さと、表示中の 3D タイルの高さ（いま読み込まれている詳しさで最大 4 万点）を地形に足して判定します。結果は地図のレイヤーとして重なるので 2D に戻っても残り、見える面積を状態欄に出します。計算は CPU のコア数に分けてワーカーで行います
- **ウィンドウ**: ダイアログ（撮像計画・画像カタログ・AI・スクリプトなど）はタイトルをドラッグして好きな位置へ動かせます（タイトルのダブルクリックで元の位置）。タイトルの ⧉ で別ウィンドウに持ち出せ、地図の横や別のモニターに置いたまま、地図を操作しながら使えます（Shift+クリックは常に手前に表示するウィンドウ。Chrome・Edge）。中身はタブと同じページで動くので、入力や結果はそのまま、ライト・ダークも追従します。持ち出したウィンドウを閉じるか ↩ でタブに戻り、ダイアログの × や「閉じる」でウィンドウも閉じます。既定では今まで通りタブの中に開きます
- **プロジェクト（`.ivproj`）**: 上部の「プロジェクト」→「保存」（Ctrl+S）で、開いているレイヤーの順番・表示・不透明度・補正・バンド割当・DRA の固定・着色と重ね方・ノーデータの値・画像に設定した投影、ベクターのスタイルとラベル、レイヤーごとのタイムラインの設定、背景地図、表示範囲と、画面構成（レイヤーパネル・ダッシュボードの幅、属性テーブルの高さと折りたたみ、左の欄の開閉、タイムラインの期間・幅・累積、ダッシュボードの集計・絞り込み・ヒートマップ）を 1 つのファイルに保存します。「開く…」か、開くボタン・ドラッグ＆ドロップで `.ivproj` を選ぶと、そのときの状態に戻ります（開いているレイヤーは閉じます）。保存は JSON で、画素は入りません。COG とサービスは URL から開き直し、ローカルファイルは名前（とサイズ）で探します。File System Access API のあるブラウザ（Chrome・Edge）では、保存時のファイルのハンドルか「最近」のハンドルで探すので、許可を 1 回押すだけで開けます。見つからないファイルはダイアログで選び直すか、省いて開けます。一時レイヤー（プロセッシングの結果）は地物ごと保存します。オルソ補正・パンシャープン・RGB 合成・モザイクの結果の画像は保存されないので、GeoTIFF に書き出してから開いてください
- **ArcGIS Web マップ**: 「プロジェクト」→「ArcGIS Web マップを開く…」で、ArcGIS Online・Enterprise の Web マップを開きます。アイテムのページ（`…/home/item.html?id=…`）、Map Viewer の URL（`…/apps/mapviewer/index.html?webmap=…`）、アイテム ID（「詳細」のポータル URL と組み合わせ。既定は ArcGIS Online）、または Web マップの JSON ファイル（「詳細」）から開けます
  - **開くもの**: フィーチャーレイヤー（定義クエリ・表示／非表示・不透明度・表示縮尺・レンダラー・ラベル）、マップサービス（表示レイヤー・レイヤーごとの定義クエリ）、タイルマップサービス、イメージサービス（レンダリングルール・モザイクルール・バンド）、ベクタータイル、WMS（レイヤーごとに 1 レイヤー）、WMTS、WFS、Web タイル、OpenStreetMap。グループレイヤーは中身を展開し（表示・不透明度・縮尺はグループのものと合わせます）、Web マップに保存されたフィーチャーコレクションは一時レイヤーにします。初期表示範囲に移動し、ブックマークは「ブックマーク」に加えます
  - **スタイル**: 単一シンボル・個別値（1 フィールド）・等級区分の esriSMS・esriSLS・esriSFS は、ビューアのスタイル（◐ で変えられます）に置き換えます。画像シンボルや複数フィールドの個別値などはレンダラーのとおりに描きます（スタイルの「サービスの表示のまま」）
  - **背景地図**: `config.json` の背景地図と URL（タイルの URL・VectorTileServer・スタイル）か名前が一致すればそれを選び、なければ背景地図のレイヤーを一番下のレイヤーとして追加します
  - 開けないレイヤー（KML・CSV・シーンレイヤーなど）は、ダイアログに理由とともに一覧します
  - **トークン**: 非公開のアイテムは「詳細」のトークンを使います。トークンはポータルと同じホスト（ArcGIS Online では `*.arcgis.com` のホストサービス）にだけ送り、他のサーバーには送りません。保存はしません
- **ArcGIS Web マップとして保存**: 「プロジェクト」→「ArcGIS Web マップとして保存…」で、開いているサービスのレイヤー（表示・不透明度・定義クエリ・スタイルをレンダラーとラベルにして）、URL のないベクターレイヤー（ファイル・一時レイヤー。1 レイヤー 5,000 件まで、全体 10 MB までのフィーチャーコレクション）、表示範囲、背景地図、ブックマークを Web マップ（バージョン 2.x）の JSON にします。書けないレイヤー（画像など）はダイアログに出ます
  - 「JSON をダウンロード」で .json に、「ポータルに保存」でポータルのアイテムに保存します（ポータル URL・トークン・ユーザー名（空欄ならトークンの持ち主）・フォルダー）。書き込む前に必ず確認し、開いた（または保存した）Web マップを上書きすることもできます
- **アプリとしてインストール（PWA）**: HTTPS で配信すると、Chrome・Edge のアドレスバーからアプリとしてインストールできます。サイトのファイルは Service Worker が保持するので、オフラインでも起動します（COG・サービス・背景地図はネットワークが必要です）。インストールしたアプリは `.ivproj` を開くアプリになり、エクスプローラーや Finder でダブルクリックすると開きます（GeoTIFF・GeoJSON・GeoPackage も「プログラムから開く」で開けます）。新しいビルドが配信されると画面下に「新しいバージョンがあります」と出て、「再読み込み」で切り替わります。`config.json` とページ本体は毎回ネットワークから取りに行くので、サーバーでの編集はすぐ反映されます。Service Worker はページとサイトのファイルに `Cross-Origin-Opener-Policy: same-origin` と `Cross-Origin-Embedder-Policy: credentialless` を付けてクロスオリジン分離し、AI の推論をマルチスレッドにします（Service Worker が入った次の読み込みから。Chrome・Edge・Firefox。Safari は対応していないので 1 スレッドのまま）。他のサイトの画像やタイルのうち CORS なしで読むものは Cookie なしで取りに行きます。サーバー側でこの 2 つのヘッダーを付けて配信しても同じです
- **移動体（AIS・ADS-B）**: 「ツール」→「移動体（AIS・ADS-B）…」で、船舶（AIS）・航空機（ADS-B）のフィードをレイヤーとして表示します。`config.json` の `movingFeeds` に登録したものを選ぶか、URL を入れて接続します（WebSocket・Server-Sent Events・GeoJSON / JSON の定期取得・ArcGIS Stream Service。`ws`・`wss`・`http`・`https` のみ）。CSV（時刻・緯度・経度の列。MarineCadastre の AIS など）や GeoJSON の履歴ファイルも開けます。ID（MMSI・ICAO）・時刻・緯度・経度・方位・針路・速度・名前・種別の属性は mmsi・icao24・lat・longitude・cog・sog・heading・callsign・shipname・timestamp などの名前から自動で見つけ（aisstream.io のような入れ子は `MetaData.MMSI` のようにつなぎます。OpenSky の `states` も読めます）、「詳細」で指定もできます。各移動体は向きに回した船・航空機の記号と直近の航跡（既定: 船 30 分・航空機 5 分）で表示し、拡大すると名前（なければ ID）を添えます。最後の報告が古いものは薄く（船 10 分・航空機 1 分）、さらに古いものは消します（船 30 分・航空機 5 分）。クリックすると最新の属性を吹き出しで表示し、レイヤー一覧で選ぶと属性テーブルにも出ます。上限は 1 レイヤー 2 万件・1 件 5,000 点（合計 200 万点）で、1 秒 500 通・1 通 2 MB（定期取得は 20 MB）を超える受信や JSON でない受信は捨てます。タイムラインを開くと、期間の終わりの時刻にいた位置を、履歴ファイルとライブで受信した分（船 24 時間・航空機 6 時間分を保持）から補間して表示します。「撮影時刻に合わせる」は選んだ画像の撮影時刻（メタデータ・ファイル名など、タイムラインと同じ）でタイムラインを開き、その時刻の位置を表示します。「ライブに戻す」で最新の位置に戻ります。フィードはプロジェクトファイルには保存されません
  - **AI 検出と照合**: 「ツール」→「AI 検出と照合…」で、検出結果（ポイント・ポリゴンのレイヤー）と移動体のフィードを選び、各検出の撮像日時（`image_time`）・画像の撮影時刻・入力した日時の ± 時間の幅（既定 10 分）に、距離（既定 500 m）以内にいた移動体を探します。結果は検出の写しに `ais_status`（一致・なし・時刻なし）・`ais_id`・`ais_name`・`ais_dist_m`・`ais_dt_s` を足した一時レイヤーで、一致しない検出（AIS を出していない船など）を赤、一致したものを緑で表示します
- **QGIS との連携**: ベクターレイヤーの「スタイル・ラベル」で「読み込み…」から QGIS などの `.sld`（SLD 1.0・SE 1.1）・`.qml` を読み込み、「書き出し…」で SLD 1.0・SLD 1.1（SE）・QML に書き出せます。単一シンボル・分類（値ごと）・段階（範囲ごと）、点の形・大きさ・塗り・線、線の色・幅・線種、面の塗りと輪郭、ラベル（属性・大きさ・色・太字・縁取り・ラベルを隠す縮尺）とレイヤーの表示縮尺を対応させ、対応する設定がないもの（ルールによる表示・模様の塗り・式のラベルなど）は省いて一覧で知らせます。「プロジェクト」→「QGIS プロジェクトを読み込む…」（または開くボタン・ドロップで `.qgs`・`.qgz`）で QGIS のプロジェクトを開きます。レイヤーツリーの順番・表示・不透明度、WMS・WMTS・XYZ タイル・WFS・ArcGIS（フィーチャーサービス・マップサービス）、ローカルのファイル（Shapefile・GeoPackage・CSV・GeoTIFF など。.ivproj と同じダイアログで選びます）、`/vsicurl/` の GeoTIFF（COG として）、ベクターのスタイルとラベル、ラスターの擬似カラー・バンドの割り当て、地図の表示範囲を読み込み、開けないレイヤー（データベース・ベクタータイル・メッシュなど）は一覧で知らせます。「QGIS 形式で書き出す」は開いているレイヤー（サービスは URL、ローカルファイルは同じフォルダーにある前提のファイル名）とスタイル・表示範囲を `.qgs` にします。XML は外部の実体を読まない専用の読み取りで読み、大きさにも上限（スタイル 5 MB・プロジェクト 50 MB）があります

サービスは、サーバーが CORS を許可している必要があります（このサイトは中継サーバーを使いません）。イメージサービス・マップサービスの画像はタイルの URL で読むので、トークンを入れたときはタイルの URL にトークンが入ります（ほかの要求は POST で送ります）。今回対応していないものは、WFS-T による WFS の編集、OGC API Features、XYZ タイルのレイヤー追加、Esri の添付ファイル・リレーションシップ・バージョン管理です。

COG は、サーバーが CORS と Range リクエストを許可している必要があります。UTM（WGS 84）の COG は追加設定なしで表示できます。それ以外の座標系は `config.json` の `projectionLookup`（既定は spatialreference.org）から定義を取得します。

## 設定ファイル（config.json）

背景地図や座標系の定義の取得先など、環境によって変えたい値は `index.html` と同じ場所の `config.json` に書きます。起動のたびに読み込むので、ビルドし直さずにサーバー上のファイルを書き換えるだけで反映されます（`npm run build` すると `public/config.json` が `dist/config.json` にコピーされます）。

ファイルがない・JSON として読めないときは組み込みの既定値で起動し、項目ごとに書かれていない・値がおかしいときはその項目だけ既定値を使います（無視した理由はブラウザのコンソールに出ます）。

```jsonc
{
  // 背景地図の一覧（「背景なし」の後に、この順で並びます）。書くとこの一覧で置き換わります
  "baseMaps": [
    {
      "id": "gsi-std",              // ?base= に入るキー
      "label": "地理院 標準",        // 切り替えに出る名前
      "url": "https://cyberjapandata.gsi.go.jp/xyz/std/{z}/{x}/{y}.png", // XYZ タイル（http(s) か相対パス）
      "attributions": "<a href=\"https://maps.gsi.go.jp/development/ichiran.html\">地理院タイル</a>", // 出典（HTML）
      "maxZoom": 18
    },
    // ベクタータイル。種類（type）は URL から判断します（書いて指定もできます）
    { "id": "appliance-osm", "label": "OSM（Data Appliance）",
      "url": "https://appliance.example.com/arcgis/rest/services/OpenStreetMap/VectorTileServer" }, // ArcGIS VectorTileServer（type: "esri"）。サーバーの既定スタイルで描きます
    { "id": "secure", "label": "社内地図", "url": "https://gis.example.com/server/rest/services/Base/VectorTileServer",
      "token": "…", "style": "https://gis.example.com/styles/dark/root.json" },          // token・別スタイル（style）は任意
    { "id": "style", "label": "地理院 ベクトル",
      "url": "https://gsi-cyberjapan.github.io/optimal_bvmap/style/std.json" },     // Mapbox / MapLibre のスタイル JSON（type: "style"）
    { "id": "pbf", "label": "ベクタータイル", "url": "https://example.com/tiles/{z}/{x}/{y}.pbf",
      "maxZoom": 14 }                                                                  // .pbf・.mvt のタイル（type: "mvt"）。組み込みの淡い配色で描きます
  ],
  // ?base= がないときに出す背景地図の id（"" で背景なし）
  "defaultBaseMap": "",
  // 未登録の座標系の定義を取る URL。{authority}（epsg など小文字）と {code}（6677 など）を置き換え、
  // OGC WKT か proj4 文字列を返すものにします。"" にすると取得しません
  "projectionLookup": "https://spatialreference.org/ref/{authority}/{code}/ogcwkt/",
  // 起動時に登録する座標系（ネットワークなしで使えます）
  "projections": {
    "EPSG:6677": "+proj=tmerc +lat_0=36 +lon_0=139.833333333333 +k=0.9999 +x_0=0 +y_0=0 +ellps=GRS80 +units=m +no_defs"
  },
  // 起動時に読み込むレイヤー。上に書いたものが下（一覧の下）になります
  "layers": [
    { "type": "cog", "url": "https://example.com/ortho.tif" },                       // COG
    { "type": "file", "url": "./data/stations.geojson" },                            // GeoJSON・Shapefile の .zip・画像・GeoTIFF
    { "type": "wms", "url": "https://example.com/wms", "layer": "roads" },           // WMS（layer はレイヤー名）
    { "type": "wmts", "url": "https://example.com/wmts", "layer": "photo",
      "matrixSet": "GoogleMapsCompatible", "format": "image/jpeg" },                 // WMTS（matrixSet・format は任意）
    { "type": "wfs", "url": "https://example.com/wfs", "layer": "test:stations" },   // WFS
    { "type": "esri", "url": "https://example.com/arcgis/rest/services/X/FeatureServer", "layer": "0" }, // Esri（layer はレイヤー ID）
```

`layers` のレイヤーは `?url=`・`?service=` のリンクで指定したものより先に開きます。共有リンクには設定ファイルのサービスレイヤーも入りますが、同じレイヤーは 1 回だけ開きます。開けなかったレイヤーは状態欄に理由を出し、残りのレイヤーは開きます。`file` はサーバーが CORS を許可している必要があります（同じサイトに置くなら不要です）。

背景地図の `type` は `xyz`（ラスタータイル）・`mvt`・`style`・`esri` のどれかで、書かなければ URL から決めます（`…/VectorTileServer` なら `esri`、`{z}` を含み `.pbf`・`.mvt` で終われば `mvt`、`{z}` を含むそれ以外は `xyz`、残りは `style`）。ベクタータイルは Web メルカトル（EPSG:3857）のものに対応します。ArcGIS のサービスは `?f=json` の情報とスタイル（`resources/styles/root.json`）を読み、タイルの `{z}/{y}/{x}` の並びとズーム範囲をサーバーの情報に合わせます。`token` はサーバーへのすべての要求（情報・スタイル・タイル・アイコン）に付けます。スタイルのアイコン（sprite）が読めないときはアイコンなしで表示し、読み込めない背景地図は理由を状態欄に出します。ラベルの文字は端末のフォントで描き、入っていないフォントは jsDelivr から取得を試みます（閉じたネットワークではその要求が失敗するだけで、代わりのフォントで描きます）。

`serviceRules` の各ルールに書けるのは次の項目です（どれも任意。書かなかったものはサービスの既定のまま）。同じものはダイアログで設定でき、`layers` の `settings`・共有リンク・プロジェクトファイルも同じ形です。

- `match`: サービスの URL に対する正規表現（大文字小文字は区別しない。省略するとすべての Esri イメージ・マップサービス）。`label` は必須、`default: true` のルールは開いたとき（リンクやプロジェクトに表示ルールがないとき）に使います
- イメージサービス: `where`（カタログの属性の SQL 条件）、`sortField`・`ascending`（並び順。既定は大きい順＝新しい順が上）、`sortValue`（その値に近い順）、`method`（重ね方。`ByAttribute`・`NorthWest`・`Center`・`Nadir`・`Seamline`・`Viewpoint`・`LockRaster`・`None`、または `esriMosaic…` の名前）、`lockRasterIds`（`LockRaster` で描く画像の ID）、`operation`（重なった画素。`MT_FIRST`・`MT_LAST`・`MT_MIN`・`MT_MAX`・`MT_MEAN`・`MT_BLEND`・`MT_SUM`）、`rasterFunction`（ラスター関数の名前。`None` で保存されている値）、`renderingRule`（レンダリングルールそのもの。`rasterFunction` より優先）、`bandIds`（0 から数えたバンド）
- マップサービス: `layers`（描くレイヤーの ID）、`layerDefs`（レイヤー ID ごとの属性の条件）

`imageRules` は、開いた画像のファイル名（URL なら最後の部分。`?` 以降は除く）を上から順に `match` の正規表現で調べ、最初に合ったルールの補正とバンド割り当てで開きます。合ったときは状態欄に「（設定「Landsat 8/9」を適用）」と出ます。開いたあとに補正パネルで変えた値がそのまま優先され、プロジェクトファイル（.ivproj）を開いたときは保存した補正・バンドに戻ります。

- `match`: ファイル名に対する正規表現（JSON なので `\` は `\\` と書きます）。大文字小文字は区別しません。区別したいときは `"caseSensitive": true`
- `label`: 状態欄に出す名前（省略すると `match`）
- `preset`: 組み込みの補正 `auto`・`vivid`・`soft`・`satellite`・`document`・`blackAndWhite` のどれか
- `enhance`: 補正の値。`{ "contrast": 0.2, "saturation": 0.1, "autoStretch": { "lowPercent": 1 } }` のように手順ごとに書くと `preset` の上に重ねます。プロジェクトファイルの `pipeline`（`{ "version": 1, "ops": [...] }`）をそのまま貼ることもできます（このときは `preset` を置き換えます）
- `bands`: R・G・B に出すバンド。`[4, 3, 2]` のように 1 から数えた番号か、`["NIR", "Red", "Green"]` のようにバンド名（混ぜても可）。`2` や `[2]` の 1 つだけならそのバンドをグレーで出します。3 バンド以上の画像でだけ使い、足りないときは状態欄に理由を出して補正だけ使います
- `noData`: 透明にする値。`0` や `[0, 255]` と書くと、ファイルのノーデータ値とよく使われる埋め値に加えて、すべてのバンドがその値の画素を透明にします。`{ "auto": false, "values": [0] }` のように `auto` を `false` にすると、ファイルのノーデータ値と埋め値は透明にしません

`imageCatalogs` の `fields` は `source` だけが必須で、ほかは書いた役割だけが検索条件と一覧の列になります。`source` の値が `http://`・`https://` で始まれば COG の URL として開き、それ以外（`\\nas\img\a.tif`・`C:\…`・`/mnt/…`・`file://…`）はローカルパスとして扱います。URL とパスを別々の属性に持つカタログは `["COG_URL", "FILE_PATH"]` のように並べると、値のある最初の属性を使います。日時の属性は日付型（`esriFieldTypeDate`）なら TIMESTAMP で、文字列なら `yyyy-mm-dd` の先頭で比べます（日付は端末の時刻で入力し、一覧も端末の時刻で表示します）。サービスが並べ替え・ページングに対応していないときは全件を受け取り、ビューアで新しい順に並べて `maxResults` 件に絞ります。センサーの選択肢はサービスの重複除去（returnDistinctValues）で作り、使えないサービスでは文字入力になります。

カタログから開いた画像は、`azimuth` と `angle` の両方があれば簡易オルソ補正の「方位角」「仰角」の初期値になります（画像に .IMD があればそちらを優先）。`angle` は既定でオフナディア角として、地球の丸みを入れて仰角に直します（衛星高度 `orbitHeight` km、既定 600。オフナディア 10° なら仰角 約 79°）。入射角なら `"angleKind": "incidence"`、仰角そのものなら `"elevation"` と書きます。

`pathMappings` はカタログのローカルパス（`\\nas\img\2026\a.tif`・`Z:\…`・`/mnt/…`・`file://…`）を開く方法です。ブラウザはパスをそのまま開けないので、先頭（`prefix`）ごとに次のどちらかを書きます。

- `url` あり: 残りのパスを URL につなげて COG として開きます（`\\nas\img\2026\a.tif` → `https://nas-web/img/2026/a.tif`）。サーバーは Range 要求と CORS に対応している必要があります。どのブラウザでも、クリックなしで開けます
- `url` なし: 初めてその先頭のパスを開くときに「フォルダを選ぶ…」を出し、`prefix` が指すフォルダ（例: ネットワークドライブの `img`）を選んでもらいます。選んだフォルダはブラウザ（IndexedDB）に覚え、次からは選ばずに開けます（ブラウザを開き直したあとは「許可する」を 1 回押すだけです）。残りのパスはそのフォルダの中をたどり（大文字小文字は区別しません）、ローカルファイルと同じく必要な部分だけ読むので、大きな画像もすぐ開きます。隣にある `.ovr`・`.RPB`・`_RPC.TXT`・`.IMD` も一緒に開き、「最近」にも入ります。File System Access API のある Chrome・Edge でだけ使えます。違うフォルダを選んだときは、カタログの「詳細条件」→「フォルダの許可を消去」で選び直せます

`stacCatalogs` の各カタログは `url` だけが必須です（URL の文字列だけでも可）。`collections` を書くとそのコレクションのチェックを並べ、書かないと API の `/collections` から選択肢を作ります（チェックなしはすべてのコレクション）。検索は POST `/search` で、POST を受け付けない API には GET で、並べ替え（`sortby`）を受け付けない API には並べ替えなしで問い合わせ直します。日付は UTC の日の始めから終わりまでです。`token`・`headers` はカタログと同じオリジンへの要求にだけ付け、`next` リンクが別のサーバーを指すとき・サムネイル・COG の読み込みには付けません（COG は認証なしで読めるか、署名付き URL である必要があります）。サムネイルは http(s) の PNG・JPEG・WebP・GIF だけを画像として表示します。`s3://` などブラウザで開けない場所のアセットは一覧に出ますが開けません。`"sign": "planetary-computer"` を書いたカタログがあると、`*.blob.core.windows.net` への要求（COG の Range 読み込みなど）に、そのストレージアカウント・コンテナーのトークン（`https://planetarycomputer.microsoft.com/api/sas/v1/token/{アカウント}/{コンテナー}`、期限まで使い回し）を要求のたびに付けます。レイヤー名・共有リンク・プロジェクトファイルには署名なしの URL だけが残り、プロジェクトを開き直したときは新しいトークンで署名し直します。トークンが得られないときは署名せずに読みます。

`satelliteCatalogs` の `fields` は TLE（`tle`、または `tle1` と `tle2`）だけが必須です。`tle` は 2 行（前に衛星名の行があってもよい）を 1 つの属性に入れた形に対応します。諸元の属性がない・空の衛星は `defaults` の値を使います。撮像機会は、点や線は対象の中心で、ポリゴンは内側の格子点のうち届く範囲（最小〜最大オフナディア角・見られる向き）に入るもので判定し、軌道の面からの距離で候補を絞ってから、パスごとに最も近づく時刻を 0.05 秒以下まで詰めます。被覆のシーン数は、その時刻の軌道に直交する方向の領域の幅 ÷ 観測幅（切り上げ）です。カタログを書かないときは、決め打ちのサンプル衛星 2 機（実在の衛星ではありません）で計算します。Sentinel-2 相当の光学衛星（高度約 786 km・太陽同期 10:30 降交・最大オフナディア角 20°・観測幅 30 km）と、Sentinel-1 相当の右向き SAR 衛星（高度約 693 km・18:00 昇交・オフナディア角 20〜45°・観測幅 50 km）です。「詳細条件」に TLE を貼り付ければ、そこで指定した諸元の衛星を足せます。

`embed` は、ほかの Web アプリがこのビューアを iframe に入れて postMessage で操作するための設定です（下の「埋め込み（iframe）」）。書かない・`allowedOrigins` が空のときは無効で、届いたメッセージはすべて無視します。

```jsonc
"embed": {
  "allowedOrigins": ["https://app.example.com"], // 操作を許すページのオリジン（スキーム・ホスト・ポートを正確に。* やパスは不可）
  "readOnly": false                              // true: 表示の移動と読み取りだけ（レイヤーの追加・変更・ツールは拒否）
}
```

`arcgisPortals` を書くと、ヘッダーに「サインイン」が出ます。ポータルを選ぶとポップアップでそのポータルのサインイン画面が開き、サインインするとボタンがユーザー名に変わります（メニューから「サインアウト」）。OAuth 2.0 の認可コード＋PKCE なので、クライアントシークレットは要りません。ポータルでアプリ（「その他のアプリケーション」/ OAuth 認証情報）を登録し、リダイレクト URI にこのサイトの `oauth-callback.html`（例: `https://viewer.example.com/oauth-callback.html`）を加えて、そのクライアント ID を `clientId` に書きます。`url` はポータルのルート（`https://www.arcgis.com`、`https://gis.example.com/portal`）で、https だけです（http は localhost のみ）。サインイン中のトークンは、そのポータル・ArcGIS Online の組織のホストサービス（`services*.arcgis.com/<組織 ID>/…`）・ポータルのフェデレーションサーバー（`portals/self/servers`）への要求に、トークンを入力しなかったときだけ自動で付けます（サービスの追加・画像カタログ・撮像計画の衛星カタログ・標高サービス・DB へ転記・ジオコーダー・イメージサービスのタイルなど）。サーバーが期限切れ・無効（498・499）と答えたら 1 回だけ更新して送り直し、期限の前にも自動で更新します。トークンはこのタブ（sessionStorage）にだけ残り、リンク・プロジェクトファイルには入りません。

`authRules` は URL の先頭（`prefix`）が一致する要求に `headers`（ヘッダー）か `query`（クエリパラメーター）を付けます。対象は COG の読み込み（Range 要求ごと）・WMS・WMTS・Esri・XYZ 背景地図のタイル・サービスの情報や地物の要求・URL で開くファイルです。`prefix` は `https://` で始まりホストの後の `/` まで含めて書き（http は localhost のみ）、文字列としての前方一致で、複数合えば最も長いものを使います。ほかのホストには送りません。ヘッダーを付ける要求は CORS の事前確認（preflight）になるので、サーバーがそのヘッダー（と `range`）を `Access-Control-Allow-Headers` で許可している必要があります。Cookie・Host などブラウザーが付けさせないヘッダーは無視します。ベクタータイル（`mvt`・`style`）の背景地図のタイルにはまだ付きません。

`movingFeeds` の `fields` に書ける役割は `id`・`time`・`lat`・`lon`・`heading`・`course`・`speed`・`name`・`kind` です。入れ子の値は `MetaData.MMSI` のように `.` でつなぎ、GeoJSON・Esri のポイントの位置は書かなくても読みます。時刻は 1970 年からの秒・ミリ秒か日時の文字列で、時差のない文字列は UTC とみなします。ArcGIS Stream Service の `url` に `?token=` を付けると説明の取得と（同じホストなら）WebSocket に使います。
`gpServices` の `url` は http(s) の URL にしてください（それ以外は理由をコンソールに出して無視します）。`label` を省くと URL を名前にします。ここに書いたサービスは「サーバ処理」を開いたときに先頭のものを読み込み、「サービス」で切り替えられます。

実際のファイルは JSON なので、コメントは書けません。`projectionLookup` を例えば `https://epsg.io/{code}.proj4` にすると epsg.io から取得します。

## 埋め込み（iframe）

ほかの Web アプリのページに `<iframe src="https://viewer.example.com/index.html?embed=1">` で入れ、`postMessage` で操作できます（`config.json` の `embed.allowedOrigins` に、そのページのオリジンを書いたときだけ）。`?embed=1` はヘッダー・レイヤーパネル・属性テーブルなどを隠して地図だけにする表示の指定で、許可には関係しません。

クライアント `embed-client.js`（ビルド不要の ES モジュール）と例 `embed-example.html` を同じ場所に置いています。

```js
import { connect } from 'https://viewer.example.com/embed-client.js';
const viewer = await connect(document.querySelector('iframe'), 'https://viewer.example.com');
await viewer.call('open', { url: 'https://data.example.com/scene.tif' });
await viewer.call('setView', { center: [139.7671, 35.6812], zoom: 14 });
await viewer.call('addShapes', { wkt: ['POLYGON((139.70 35.65, 139.80 35.65, 139.80 35.72, 139.70 35.65))'], labels: ['区域'], name: '対象' });
viewer.on('click', ({ lon, lat }) => console.log(lon, lat));
```

- メッセージ: 要求 `{ type: 'image-viewer', v: 1, id, method, params }` → 応答 `{ type, v, id, result }` か `{ type, v, id, error: { code, message } }`。イベントは `{ type, v, event, data }`。最初に `hello`（`params.events` で受け取るイベントを絞れます）を送ると、以後そのオリジンにだけイベントを送ります
- メソッド: `hello`・`getView`・`setView`（`center` [経度, 緯度]・`zoom`・`resolution`・`rotation`・`bbox` [西, 南, 東, 北]・`duration`）・`zoomTo`・`listLayers`・`selectLayer`・`getSelection`（`features: true` で選択地物の GeoJSON も）・`listBaseMaps`・`listTools`、変更するもの: `open`（`url`・`type` cog / file / wms / wmts / wfs / esri・`layer` ほか）・`setVisible`・`setOpacity`・`removeLayer`・`setBaseMap`・`addShapes`（`wkt` / 座標の配列・`geojson`・`labels`・`name`・`color`・`zoom`。リンクの図形と同じ読み方と上限で一時レイヤーに）・`runTool`（ツールのダイアログを `params` で埋めて実行。スクリプトの `viewer.tool` と同じ。表示範囲の保存は不可）。レイヤーは `listLayers` の `id` で指定します
- イベント: `ready`（起動時のレイヤーを開き終えた）・`view`（表示範囲。200 ms に 1 回まで）・`selection`（選択地物の id）・`layers`（レイヤー一覧）・`click`（地図のクリック地点の `lon`・`lat`）
- 安全: 親ウィンドウ（`event.source`）で、許可したオリジン（`event.origin`）のメッセージだけを読み、応答もそのオリジンにだけ送ります。メソッドは決まった一覧だけで、パラメーターは型と範囲を厳密に確かめ、要求は 1,000,000 文字・応答は 8,000,000 文字まで、同時に 8 件までです。中身を実行することはありません。地物の編集・保存・ダウンロード・ファイルを開くことはできず、ビューアがまだ使っていないサーバーを開くときは利用者に確認します（スクリプトと同じ）。`readOnly` では変更するメソッドを拒否します
- 配置: 許可したページ以外に iframe で入れられないよう、Web サーバーで `Content-Security-Policy: frame-ancestors 'self' https://app.example.com`（`allowedOrigins` と同じオリジン）を返してください（古いブラウザ向けの `X-Frame-Options` は 1 オリジンしか書けないので、埋め込むときは使わず CSP にします）。埋め込みを使わないサイトでは `frame-ancestors 'self'` が安全です

## 動かし方

リポジトリのルートで `npm ci` したあと:

```sh
cd usecase/image-viewer
npm run dev        # 開発サーバー
npm run build      # dist/ に静的サイトを出力（相対パスなので任意の場所に置ける）
npm run test:browser
```

ライブラリはワークスペース経由で `packages/browser-image-enhancement/dist` を使います。ライブラリのソースを変えたときは、先に `packages/browser-image-enhancement` で `npm run build` してください。

## 閉域への持ち込み

`npm run build` のあと `npm run package` で、`release/image-viewer-<日付>-<コミット>.zip`（例: `image-viewer-20261007-fa088f0.zip`）を作ります。中身は `image-viewer/` フォルダにサイト一式と `README.txt`（置き方と config.json の直し方）です。外部の CDN は使っていないので、閉域内の Web サーバーにコピーすれば動きます（`file://` では動きません）。背景地図と座標系の検索先はインターネットを指しているので、閉域では `config.json` の `baseMaps` と `projectionLookup` を書き換えてください。

デプロイのたびに同じ zip を作り、Actions の実行結果の Artifacts（90 日保存）と、サーバーの `download/image-viewer.zip`（最新のみ）に置きます。

## デプロイ（VPS）

`.github/workflows/deploy-image-viewer.yml` が、既定ブランチへの push（マージ）で CI が通ったあと、`dist/` を VPS へ SFTP（lftp、パスワード認証）で転送します。Actions タブから手動実行（workflow_dispatch）もできます。

リポジトリシークレット: `VPS_HOST`、`VPS_USER`、`VPS_USER_PASSWORD`、`IMAGE_VIEWER_DEPLOY_DIRECTORY`（無ければ作成。相対パスはユーザーのホームから）、任意で `VPS_PORT`（既定 22）。

- `config.json` はサーバーに無いときだけ置きます。サーバー上で編集した設定はデプロイで上書きされません（初期値に戻したいときはサーバー上のファイルを消して再デプロイ）。
- それ以外のファイルは置き換え、古いビルドの不要ファイルは削除します。
